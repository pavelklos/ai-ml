## 1. Introduction to Logging and Debugging

Effective logging and debugging are essential skills for Python developers. Logging helps track application behavior and diagnose issues, while debugging allows you to investigate and fix problems during development. Together, they form a powerful toolkit for maintaining reliable software.

```python
# Common approaches to troubleshooting code

# Approach 1: Print statements (not recommended for production)
def calculate_total(items):
    print(f"Starting calculation with {len(items)} items")
    total = 0
    for item in items:
        print(f"Adding item: {item}")
        total += item
    print(f"Final total: {total}")
    return total

# Approach 2: Using assertions to catch logical errors
def calculate_average(numbers):
    assert len(numbers) > 0, "Cannot calculate average of empty list"
    total = sum(numbers)
    return total / len(numbers)

# Approach 3: Structured logging (better approach)
import logging
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def process_order(order):
    logger.info(f"Processing order #{order['id']}")
    if order['status'] == 'paid':
        logger.debug(f"Order details: {order}")
        # Process the order
        return True
    else:
        logger.warning(f"Order #{order['id']} not paid")
        return False
```

## 2. Basic Logging with the logging Module

Python's built-in `logging` module provides a flexible framework for emitting log messages from your programs. It offers more functionality than simple print statements, including log levels, formatting options, and the ability to output to different destinations.

```python
import logging

# Basic configuration
logging.basicConfig(
    level=logging.INFO,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    filename='app.log'
)

# Using different log levels
logging.debug("This is a debug message")    # Won't show (below INFO level)
logging.info("Application started")
logging.warning("Configuration file not found, using defaults")
logging.error("Could not process request")
logging.critical("Database connection failed")

# Creating a named logger
logger = logging.getLogger("my_application")
logger.info("This message comes from my application logger")

# Log levels in order of severity:
# DEBUG < INFO < WARNING < ERROR < CRITICAL
```

Log levels provide a way to categorize messages by importance:
- DEBUG: Detailed information, typically only valuable when diagnosing problems
- INFO: Confirmation that things are working as expected
- WARNING: An indication that something unexpected happened, or may happen in the future
- ERROR: Due to a more serious problem, the software couldn't perform some function
- CRITICAL: A serious error, indicating the program itself may be unable to continue running

## 3. Configuring Loggers

Logging can be configured in several ways, from simple to complex, depending on your application's needs.

```python
import logging
import logging.config
import json
import yaml
import os

# Basic configuration with console and file handlers
def setup_basic_logging():
    logger = logging.getLogger("my_app")
    logger.setLevel(logging.DEBUG)
    
    # Console handler
    console = logging.StreamHandler()
    console.setLevel(logging.INFO)
    console_format = logging.Formatter('%(name)s - %(levelname)s - %(message)s')
    console.setFormatter(console_format)
    
    # File handler
    file_handler = logging.FileHandler("app_debug.log")
    file_handler.setLevel(logging.DEBUG)
    file_format = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')
    file_handler.setFormatter(file_format)
    
    # Add handlers to logger
    logger.addHandler(console)
    logger.addHandler(file_handler)
    
    return logger

# Configuration using a dictionary
def setup_dict_config():
    config = {
        'version': 1,
        'formatters': {
            'standard': {
                'format': '%(asctime)s - %(name)s - %(levelname)s - %(message)s'
            },
        },
        'handlers': {
            'console': {
                'class': 'logging.StreamHandler',
                'level': 'INFO',
                'formatter': 'standard',
                'stream': 'ext://sys.stdout'
            },
            'file': {
                'class': 'logging.FileHandler',
                'level': 'DEBUG',
                'formatter': 'standard',
                'filename': 'app.log',
                'mode': 'a',
            }
        },
        'loggers': {
            'my_app': {
                'handlers': ['console', 'file'],
                'level': 'DEBUG',
                'propagate': False
            }
        }
    }
    logging.config.dictConfig(config)
    return logging.getLogger('my_app')

# Configuration using a file (YAML example)
def setup_yaml_config(config_path='logging.yaml'):
    if os.path.exists(config_path):
        with open(config_path, 'rt') as f:
            config = yaml.safe_load(f.read())
        logging.config.dictConfig(config)
    else:
        logging.basicConfig(level=logging.INFO)
    return logging.getLogger('my_app')

# Example usage
logger = setup_basic_logging()
logger.debug("Debug message")
logger.info("Info message")
logger.warning("Warning message")
```

## 4. Advanced Logging Features

The logging module offers many advanced features to help you handle complex logging requirements.

```python
import logging
import logging.handlers
import sys
import traceback

# Rotating file handler (limits file size)
def setup_rotating_logs():
    logger = logging.getLogger("rotating_example")
    logger.setLevel(logging.DEBUG)
    
    # 5 MB per file, keep 5 backup files
    handler = logging.handlers.RotatingFileHandler(
        "app.log", maxBytes=5*1024*1024, backupCount=5
    )
    formatter = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')
    handler.setFormatter(formatter)
    logger.addHandler(handler)
    return logger

# Time-based rotation
def setup_timed_logs():
    logger = logging.getLogger("timed_example")
    logger.setLevel(logging.DEBUG)
    
    # Creates a new log file at midnight
    handler = logging.handlers.TimedRotatingFileHandler(
        "app.log", when="midnight", interval=1, backupCount=7
    )
    formatter = logging.Formatter('%(asctime)s - %(name)s - %(levelname)s - %(message)s')
    handler.setFormatter(formatter)
    logger.addHandler(handler)
    return logger

# Capturing stack traces with exceptions
def log_exception(logger):
    try:
        1 / 0  # Generate a ZeroDivisionError
    except Exception as e:
        # Method 1: Just use exception info
        logger.error("An error occurred: %s", str(e), exc_info=True)
        
        # Method 2: Manually format exception
        logger.error("An error occurred: %s\n%s", str(e), traceback.format_exc())

# Custom logger class
class CustomAdapter(logging.LoggerAdapter):
    def process(self, msg, kwargs):
        # Add user ID to all log messages
        user_id = kwargs.pop('user_id', 'unknown')
        return f"[User: {user_id}] {msg}", kwargs

# Example usage
logger = setup_rotating_logs()
adapter = CustomAdapter(logger, {})

adapter.info("User logged in", user_id="12345")
log_exception(logger)
```

## 5. Using the Python Debugger (pdb)

The Python Debugger (pdb) is a powerful tool that allows you to step through your code, inspect variables, and understand program flow.

```python
import pdb

def complex_function(data):
    result = []
    for item in data:
        # Set a breakpoint programmatically
        if item < 0:
            pdb.set_trace()  # The debugger will start here when item < 0
        
        processed = item * 2
        result.append(processed)
    
    return result

# In Python 3.7+, you can also use the builtin breakpoint() function
def another_function():
    x = 10
    y = 20
    breakpoint()  # Debugger will start here
    z = x + y
    return z

# Example of running it
data = [1, 5, -3, 10]
result = complex_function(data)

# pdb commands (to use when the debugger is active):
# n (next) - Execute current line and move to next line
# s (step) - Step into a function call
# c (continue) - Continue execution until next breakpoint
# q (quit) - Quit the debugger
# l (list) - Show current location in code
# p expression - Print the value of an expression
# pp expression - Pretty print the value of an expression
# h (help) - Show help
# b line_number - Set a breakpoint at line_number
```

### Using pdb with Post-Mortem Debugging

```python
import pdb

def divide(a, b):
    return a / b

def calculate():
    try:
        result = divide(10, 0)
    except Exception:
        # Enter post-mortem debugging when an exception occurs
        pdb.post_mortem()
        # or: pdb.pm()  

# Run this in a script
# calculate()

# To debug a traceback from an exception that already occurred:
def demonstrate_pm():
    import sys
    import traceback
    
    try:
        divide(1, 0)
    except Exception:
        # Save the traceback information
        type, value, tb = sys.exc_info()
        traceback.print_exc()
        pdb.pm()  # Start post-mortem debugging
```

## 6. Debug Helpers and Best Practices

Beyond basic logging and pdb, Python offers other tools and techniques to help with debugging.

```python
# Using assertions for debugging
def calculate_discount(price, discount_rate):
    assert 0 <= discount_rate <= 1, f"Discount rate must be between 0 and 1, got {discount_rate}"
    return price * (1 - discount_rate)

# Example of a custom debugging decorator
import functools
import time

def debug_function_calls(func):
    """Decorator that logs function calls with arguments and return values"""
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        args_repr = [repr(a) for a in args]
        kwargs_repr = [f"{k}={v!r}" for k, v in kwargs.items()]
        signature = ", ".join(args_repr + kwargs_repr)
        
        print(f"Calling {func.__name__}({signature})")
        start_time = time.time()
        
        try:
            result = func(*args, **kwargs)
            print(f"{func.__name__} returned {result!r}")
        except Exception as e:
            print(f"{func.__name__} raised {type(e).__name__}: {e}")
            raise
        finally:
            end_time = time.time()
            print(f"{func.__name__} took {(end_time - start_time)*1000:.2f}ms to execute")
        
        return result
    return wrapper

@debug_function_calls
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

# Example usage
result = fibonacci(5)

# Debugging best practices:
# 1. Use meaningful variable names
# 2. Add comments to complex sections
# 3. Break complex functions into smaller ones
# 4. Use type hints to catch type errors early
```

## 7. Debugging in Production

In production environments, debugging strategies need to be different due to performance considerations and security concerns.

```python
import logging
import sys
import traceback
from logging.handlers import SMTPHandler, RotatingFileHandler

# Setting up production logging
def setup_production_logging():
    # Application logger
    logger = logging.getLogger('my_app')
    logger.setLevel(logging.INFO)
    
    # Regular application logs
    file_handler = RotatingFileHandler(
        'app.log', maxBytes=10*1024*1024, backupCount=10
    )
    file_handler.setFormatter(logging.Formatter(
        '%(asctime)s %(levelname)s: %(message)s [in %(pathname)s:%(lineno)d]'
    ))
    file_handler.setLevel(logging.INFO)
    logger.addHandler(file_handler)
    
    # Error logs with email notifications for critical errors
    if not sys.debug:  # Only in production
        mail_handler = SMTPHandler(
            mailhost=('smtp.example.com', 587),
            fromaddr='server@example.com',
            toaddrs=['admin@example.com'],
            subject='Application Error',
            credentials=('username', 'password'),
            secure=()
        )
        mail_handler.setLevel(logging.ERROR)
        logger.addHandler(mail_handler)
        
    return logger

# Global exception handler
def configure_global_exception_handler(logger):
    def handle_exception(exc_type, exc_value, exc_traceback):
        if issubclass(exc_type, KeyboardInterrupt):
            # Don't log keyboard interrupt (Ctrl+C)
            sys.__excepthook__(exc_type, exc_value, exc_traceback)
            return
            
        logger.critical("Uncaught exception", 
                      exc_info=(exc_type, exc_value, exc_traceback))
    
    sys.excepthook = handle_exception

# Structured contextual logging for tracking requests/users
class RequestContextAdapter(logging.LoggerAdapter):
    def process(self, msg, kwargs):
        request_id = self.extra.get('request_id', 'unknown')
        user_id = self.extra.get('user_id', 'anonymous')
        return f"[Request: {request_id}][User: {user_id}] {msg}", kwargs

# Example of logging in a web application context
def handle_request(request, logger):
    context = {
        'request_id': request.get('id', 'unknown'),
        'user_id': request.get('user_id', 'anonymous')
    }
    request_logger = RequestContextAdapter(logger, context)
    
    try:
        request_logger.info("Processing request")
        # Process request...
        if 'error' in request:
            raise ValueError("Invalid request parameter")
        request_logger.info("Request processed successfully")
        return {"status": "success"}
    except Exception as e:
        request_logger.error(f"Error processing request: {str(e)}", exc_info=True)
        return {"status": "error", "message": str(e)}

# Example usage
logger = setup_production_logging()
configure_global_exception_handler(logger)

fake_request = {
    'id': '12345',
    'user_id': 'user789',
    'error': True
}

response = handle_request(fake_request, logger)
```

## 8. Summary

Effective logging and debugging are essential skills for Python development. The key points to remember are:

1. **Use the logging module** instead of print statements for proper log management.

2. **Configure logging appropriately** for your application's needs, with the right log levels, handlers, and formatters.

3. **Choose the right log level** to ensure you capture necessary information without overwhelming your logs.

4. **The Python debugger (pdb)** provides powerful tools for interactive debugging during development.

5. **Advanced logging techniques** like log rotation, custom formatters, and context adapters help manage logs in complex applications.

6. **Debugging best practices** include using assertions, custom decorators, and maintaining clear, testable code.

7. **Production debugging** requires special consideration for security, performance, and capturing enough context to diagnose issues.

By mastering these techniques, you'll be better equipped to develop, maintain, and troubleshoot Python applications throughout their lifecycle.
