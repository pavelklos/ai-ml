# Python Unit Testing with unittest and pytest

## Introduction to Unit Testing

Unit testing is a software testing method where individual units or components of software are tested in isolation. The purpose is to validate that each unit of code performs as expected. A unit is the smallest testable part of an application, usually a function, method, or class.

## 2. Unit Testing Concepts

### Why Unit Testing?

- **Early Bug Detection**: Catch bugs early in the development cycle
- **Code Quality**: Improve code quality through structured testing
- **Refactoring Confidence**: Safely refactor code with tests as a safety net
- **Documentation**: Tests serve as documentation for how your code should behave

### Key Terminology

- **Test Case**: A set of conditions used to determine if a feature works correctly
- **Test Suite**: Collection of test cases
- **Test Fixture**: Environment/state needed to run tests
- **Test Runner**: Component that executes tests and provides results
- **Assertion**: Method to check if the expected output matches the actual output

Let's create a simple function to test throughout this notebook:

```python
def add_numbers(a, b):
    """Add two numbers and return the result."""
    return a + b

def multiply_numbers(a, b):
    """Multiply two numbers and return the result."""
    return a * b

class Calculator:
    """A simple calculator class."""
    
    def __init__(self):
        self.result = 0
        
    def add(self, a, b=None):
        """Add a value or two values."""
        if b is None:
            self.result += a
        else:
            self.result = a + b
        return self.result
    
    def subtract(self, a, b=None):
        """Subtract a value or two values."""
        if b is None:
            self.result -= a
        else:
            self.result = a - b
        return self.result
    
    def multiply(self, a, b=None):
        """Multiply by a value or two values."""
        if b is None:
            self.result *= a
        else:
            self.result = a * b
        return self.result
    
    def divide(self, a, b=None):
        """Divide by a value or two values."""
        if b is None:
            if a == 0:
                raise ValueError("Cannot divide by zero")
            self.result /= a
        else:
            if b == 0:
                raise ValueError("Cannot divide by zero")
            self.result = a / b
        return self.result
    
    def clear(self):
        """Reset the calculator."""
        self.result = 0
        return self.result
```

## 3. Testing with the unittest Module

`unittest` is Python's built-in testing framework that provides tools for constructing and running tests.

### Basic Structure of a unittest Test

```python
import unittest

# Import the code to be tested
from your_module import add_numbers

class TestAddFunction(unittest.TestCase):
    
    def test_add_positive_numbers(self):
        """Test adding two positive numbers."""
        result = add_numbers(2, 3)
        self.assertEqual(result, 5)
    
    def test_add_negative_numbers(self):
        """Test adding two negative numbers."""
        result = add_numbers(-2, -3)
        self.assertEqual(result, -5)
    
    def test_add_mixed_numbers(self):
        """Test adding a positive and a negative number."""
        result = add_numbers(2, -3)
        self.assertEqual(result, -1)

if __name__ == '__main__':
    unittest.main()
```

## 4. Creating Test Cases with unittest

Test cases in unittest are created by subclassing `unittest.TestCase`. Each test method must start with `test_`.

```python
import unittest

class TestCalculator(unittest.TestCase):
    
    def test_add_method(self):
        calc = Calculator()
        self.assertEqual(calc.add(5, 3), 8)
    
    def test_subtract_method(self):
        calc = Calculator()
        self.assertEqual(calc.subtract(10, 4), 6)
    
    def test_multiply_method(self):
        calc = Calculator()
        self.assertEqual(calc.multiply(2, 3), 6)
    
    def test_divide_method(self):
        calc = Calculator()
        self.assertEqual(calc.divide(10, 2), 5)
    
    def test_divide_by_zero(self):
        calc = Calculator()
        with self.assertRaises(ValueError):
            calc.divide(10, 0)
```

### Common Assertion Methods

```python
def test_assertion_examples(self):
    # Test equality
    self.assertEqual(add_numbers(2, 2), 4)
    
    # Test inequality
    self.assertNotEqual(add_numbers(2, 2), 5)
    
    # Test boolean conditions
    self.assertTrue(add_numbers(2, 2) == 4)
    self.assertFalse(add_numbers(2, 2) == 5)
    
    # Test if something is None or not None
    self.assertIsNone(None)
    self.assertIsNotNone(add_numbers(2, 2))
    
    # Test membership
    self.assertIn(2, [1, 2, 3])
    self.assertNotIn(5, [1, 2, 3])
    
    # Test exceptions
    with self.assertRaises(ValueError):
        # This should raise a ValueError
        Calculator().divide(5, 0)
```

## 6. Test Fixtures with unittest

Test fixtures are used to set up a consistent environment for tests. In unittest, we use `setUp()` and `tearDown()` methods.

```python
import unittest

class TestCalculatorWithFixture(unittest.TestCase):
    
    def setUp(self):
        """Set up test fixtures before each test method."""
        print("Setting up test case")
        self.calc = Calculator()
        self.calc.add(10)  # Initialize with value 10
    
    def tearDown(self):
        """Clean up after each test method."""
        print("Tearing down test case")
        del self.calc
    
    def test_add_with_fixture(self):
        """Test addition using the fixture."""
        self.assertEqual(self.calc.add(5), 15)
    
    def test_subtract_with_fixture(self):
        """Test subtraction using the fixture."""
        self.assertEqual(self.calc.subtract(3), 7)
    
    def test_clear_with_fixture(self):
        """Test clear method using the fixture."""
        self.assertEqual(self.calc.clear(), 0)
```

### Class Level Fixtures

```python
import unittest

class TestWithClassLevelFixtures(unittest.TestCase):
    
    @classmethod
    def setUpClass(cls):
        """Set up class fixture before running tests in the class."""
        print("Setting up class fixture")
        cls.shared_resource = {"data": "This is shared across all tests"}
    
    @classmethod
    def tearDownClass(cls):
        """Tear down class fixture after running all tests in the class."""
        print("Tearing down class fixture")
        del cls.shared_resource
    
    def test_using_class_fixture(self):
        """Test using the class fixture."""
        self.assertEqual(self.shared_resource["data"], "This is shared across all tests")
```

## 10. pytest Fixtures

Fixtures in pytest are more powerful than unittest fixtures. They are defined using the `@pytest.fixture` decorator.

```python
import pytest

@pytest.fixture
def calculator():
    """Fixture that creates a calculator instance."""
    print("Setting up calculator fixture")
    calc = Calculator()
    calc.add(10)  # Initialize with value 10
    yield calc  # This is what's returned to the test
    print("Tearing down calculator fixture")
    # Any cleanup code goes here

def test_add_with_fixture(calculator):
    """Test that uses the calculator fixture."""
    assert calculator.add(5) == 15

def test_subtract_with_fixture(calculator):
    """Another test using the calculator fixture."""
    assert calculator.subtract(3) == 7

def test_without_fixture():
    """This test doesn't use the fixture."""
    calc = Calculator()
    assert calc.add(2, 2) == 4
```

### Fixture Scope

pytest fixtures can have different scopes:

```python
@pytest.fixture(scope="function")  # Default: runs once per test function
def function_fixture():
    return {}

@pytest.fixture(scope="class")  # Runs once per test class
def class_fixture():
    return {}

@pytest.fixture(scope="module")  # Runs once per module (file)
def module_fixture():
    return {}

@pytest.fixture(scope="session")  # Runs once per pytest session
def session_fixture():
    return {}
```

### Fixture with Finalizer (Alternative to yield)

```python
import pytest

@pytest.fixture
def calculator_with_finalizer(request):
    """Fixture that uses a finalizer for cleanup."""
    calc = Calculator()
    calc.add(10)
    
    def fin():
        """Cleanup function that runs after the test is complete."""
        print("Finalizing calculator fixture")
    
    request.addfinalizer(fin)
    return calc
```

## 12. Mocking in Tests

Mocking is used to replace parts of your system under test with mock objects to isolate what you are testing.

### Using unittest.mock with unittest

```python
import unittest
from unittest.mock import MagicMock, patch

class ExternalAPI:
    def get_data(self):
        # In a real scenario, this might make a network call
        # For testing, we want to mock this
        pass

class Service:
    def __init__(self, api):
        self.api = api
        
    def process_data(self):
        data = self.api.get_data()
        if data:
            return data.upper()
        return "No data"

class TestServiceWithMock(unittest.TestCase):
    
    def test_process_data(self):
        # Create a mock for the API
        mock_api = MagicMock()
        
        # Set the return value for the get_data method
        mock_api.get_data.return_value = "test data"
        
        # Create service with the mock API
        service = Service(mock_api)
        
        # Call the method under test
        result = service.process_data()
        
        # Verify the result
        self.assertEqual(result, "TEST DATA")
        
        # Verify that get_data was called
        mock_api.get_data.assert_called_once()
    
    @patch('__main__.ExternalAPI')
    def test_process_data_with_patch(self, mock_api_class):
        # Configure the mock
        mock_api_instance = mock_api_class.return_value
        mock_api_instance.get_data.return_value = "patched data"
        
        # Create a real Service with the mocked API
        api = ExternalAPI()  # This will use the mock
        service = Service(api)
        
        # Call the method under test
        result = service.process_data()
        
        # Verify the result
        self.assertEqual(result, "PATCHED DATA")
```

### Using mocks with pytest

```python

def test_process_data_with_monkeypatch(monkeypatch):
    # Create a mock for get_data
    def mock_get_data():
        return "monkeypatched data"
    
    # Create real objects
    api = ExternalAPI()
    monkeypatch.setattr(api, 'get_data', mock_get_data)
    service = Service(api)
    
    # Test
    result = service.process_data()
    assert result == "MONKEYPATCHED DATA"

# Using pytest with unittest.mock patch
@pytest.mark.parametrize("mock_data, expected", [
    ("test data", "TEST DATA"),
    (None, "No data"),
    ("", "No data")
])
def test_process_data_parametrized(mock_data, expected):
    with patch.object(ExternalAPI, 'get_data', return_value=mock_data):
        api = ExternalAPI()
        service = Service(api)
        assert service.process_data() == expected
```

## 14. Best Practices for Unit Testing

### 1. Test Naming and Organization

```python
class TestCalculator(unittest.TestCase):
    # Pattern: test_[what's being tested]_[condition]_[expected result]
    
    def test_add_positive_numbers_returns_sum(self):
        calc = Calculator()
        self.assertEqual(calc.add(2, 3), 5)
    
    def test_divide_by_zero_raises_value_error(self):
        calc = Calculator()
        with self.assertRaises(ValueError):
            calc.divide(5, 0)
```

### 2. Arrange-Act-Assert Pattern

```python
def test_calculator_using_arrange_act_assert():
    # Arrange
    calc = Calculator()
    expected_result = 5
    
    # Act
    actual_result = calc.add(2, 3)
    
    # Assert
    assert actual_result == expected_result
```

### 3. Keep Tests Independent

```python
# GOOD: Each test is independent
def test_calculator_add_independently():
    calc = Calculator()
    assert calc.add(2, 3) == 5

def test_calculator_subtract_independently():
    calc = Calculator()
    assert calc.subtract(5, 3) == 2

# BAD: Tests depend on each other
def test_calculator_sequence():
    calc = Calculator()
    assert calc.add(2, 3) == 5  # If this fails, next test also fails
    assert calc.subtract(5, 3) == 2  # Depends on the previous test
```

### 4. Test Edge Cases

```python
def test_calculator_edge_cases():
    calc = Calculator()
    
    # Edge case: Adding zero
    assert calc.add(5, 0) == 5
    
    # Edge case: Very large numbers
    assert calc.add(10**10, 10**10) == 2 * 10**10
    
    # Edge case: Negative numbers
    assert calc.subtract(10, 15) == -5
```

### 5. Don't Test Implementation Details

```python
# GOOD: Testing the public interface
def test_calculator_public_interface():
    calc = Calculator()
    assert calc.add(2, 3) == 5

# BAD: Testing implementation details
def test_calculator_implementation_details():
    calc = Calculator()
    calc.result = 10  # Directly manipulating internal state
    assert calc.result == 10  # Testing internal state
```

### 6. Use Appropriate Assertions

```python
def test_with_appropriate_assertions():
    calc = Calculator()
    
    # For equality checks
    assert calc.add(2, 3) == 5
    
    # For exceptions
    with pytest.raises(ValueError, match="Cannot divide by zero"):
        calc.divide(5, 0)
    
    # For approximate equality (floating point)
    assert calc.divide(1, 3) == pytest.approx(0.333333, abs=1e-6)
```

## Complete Example: A More Complex Test Suite

Let's create a more complex example testing a hypothetical user management system:

```python
# user.py - The code we want to test
class User:
    def __init__(self, user_id, name, email):
        self.user_id = user_id
        self.name = name
        self.email = email
        self.is_active = True
        
    def deactivate(self):
        self.is_active = False
        
    def activate(self):
        self.is_active = True
        
    def update_email(self, new_email):
        if '@' not in new_email:
            raise ValueError("Invalid email format")
        self.email = new_email
        
class UserManager:
    def __init__(self):
        self.users = {}
        
    def add_user(self, user):
        if user.user_id in self.users:
            raise ValueError(f"User with ID {user.user_id} already exists")
        self.users[user.user_id] = user
        return user
        
    def get_user(self, user_id):
        if user_id not in self.users:
            raise ValueError(f"User with ID {user_id} not found")
        return self.users[user_id]
        
    def delete_user(self, user_id):
        if user_id not in self.users:
            raise ValueError(f"User with ID {user_id} not found")
        user = self.users.pop(user_id)
        return user
        
    def get_active_users(self):
        return [user for user in self.users.values() if user.is_active]
```

Now let's test this code:

```python
# test_user.py - Our test file
import pytest
from user import User, UserManager

class TestUser:
    """Tests for the User class."""
    
    def test_user_initialization(self):
        """Test that a user is properly initialized."""
        user = User(1, "John Doe", "john@example.com")
        assert user.user_id == 1
        assert user.name == "John Doe"
        assert user.email == "john@example.com"
        assert user.is_active is True
    
    def test_user_deactivate(self):
        """Test that a user can be deactivated."""
        user = User(1, "John Doe", "john@example.com")
        user.deactivate()
        assert user.is_active is False
    
    def test_user_activate(self):
        """Test that a user can be activated."""
        user = User(1, "John Doe", "john@example.com")
        user.deactivate()
        user.activate()
        assert user.is_active is True
    
    def test_update_email_valid(self):
        """Test that a user's email can be updated with a valid email."""
        user = User(1, "John Doe", "john@example.com")
        user.update_email("newemail@example.com")
        assert user.email == "newemail@example.com"
    
    def test_update_email_invalid(self):
        """Test that updating with an invalid email raises ValueError."""
        user = User(1, "John Doe", "john@example.com")
        with pytest.raises(ValueError):
            user.update_email("invalid-email")

class TestUserManager:
    """Tests for the UserManager class."""
    
    @pytest.fixture
    def manager(self):
        """Fixture that returns a new UserManager."""
        return UserManager()
    
    @pytest.fixture
    def sample_user(self):
        """Fixture that returns a sample user."""
        return User(1, "John Doe", "john@example.com")
    
    def test_add_user(self, manager, sample_user):
        """Test adding a user to the manager."""
        user = manager.add_user(sample_user)
        assert user is sample_user
        assert len(manager.users) == 1
        assert manager.users[1] is sample_user
    
    def test_add_duplicate_user(self, manager, sample_user):
        """Test that adding a duplicate user raises ValueError."""
        manager.add_user(sample_user)
        duplicate_user = User(1, "Jane Doe", "jane@example.com")
        with pytest.raises(ValueError):
            manager.add_user(duplicate_user)
    
    def test_get_user(self, manager, sample_user):
        """Test getting a user from the manager."""
        manager.add_user(sample_user)
        retrieved_user = manager.get_user(1)
        assert retrieved_user is sample_user
    
    def test_get_nonexistent_user(self, manager):
        """Test that getting a nonexistent user raises ValueError."""
        with pytest.raises(ValueError):
            manager.get_user(999)
    
    def test_delete_user(self, manager, sample_user):
        """Test deleting a user from the manager."""
        manager.add_user(sample_user)
        deleted_user = manager.delete_user(1)
        assert deleted_user is sample_user
        assert len(manager.users) == 0
```

## Test Driven Development (TDD) Example

### Step 1: Write the Test First

```python
    """Test that items can be popped from the stack."""

    stack.push(1)

    assert item == 2
    assert stack.size() == 1

    stack.push(1)
    stack.push(2)
    assert stack.peek() == 2
    assert stack.size() == 2  # Size doesn't change after peek
```

### Step 2: Implement the Stack Class to Make Tests Pass

```python
class Stack:
    """A simple stack implementation."""
    
    def __init__(self):
        """Initialize an empty stack."""
        self._items = []
        
    def is_empty(self):
        """Check if the stack is empty."""
        return len(self._items) == 0
        
    def size(self):
        """Return the number of items in the stack."""
        return len(self._items)
        
    def push(self, item):
        """Add an item to the top of the stack."""
        self._items.append(item)
        
    def pop(self):
        """Remove and return the top item from the stack."""
        if self.is_empty():
            raise IndexError("Cannot pop from empty stack")
        return self._items.pop()
        
    def peek(self):
        """Return the top item without removing it."""
        if self.is_empty():
            raise IndexError("Cannot peek at empty stack")
        return self._items[-1]
```

## Conclusion

Unit testing is an essential skill for Python developers. Both `unittest` and `pytest` provide powerful tools for testing your code, ensuring it works as expected and continues to do so as the code evolves.

Key takeaways:

1. **Write tests early**: Adopt a test-driven development approach whenever possible.
2. **Keep tests independent**: Each test should run independently of others.
3. **Test edge cases**: Don't just test the happy path, but also error conditions and edge cases.
4. **Use appropriate assertions**: Be specific about what you're checking.
5. **Use fixtures**: Set up repeatable test environments to avoid duplication.
6. **Keep tests fast**: Slow tests discourage regular testing.
7. **Mock external dependencies**: Use mocking to isolate your code from external systems.
8. **Measure coverage**: Know what parts of your code are tested and which aren't.
9. **Integrate with CI**: Make testing part of your regular workflow.
10. **Document your tests**: Tests serve as documentation for how your code should behave.

By following these best practices and using the right tools, you'll create more reliable, maintainable code that you can refactor with confidence.
