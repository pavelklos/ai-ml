## 1. Introduction to Advanced Decorators

Decorators are a powerful feature in Python that allow you to modify or extend the behavior of functions or methods without changing their source code. Basic decorators are functions that take another function as an argument and return a new function that usually extends the original function's behavior.

```python
# Basic decorator review
def simple_decorator(func):
    def wrapper(*args, **kwargs):
        print("Something is happening before the function is called.")
        result = func(*args, **kwargs)
        print("Something is happening after the function is called.")
        return result
    return wrapper

@simple_decorator
def say_hello(name):
    print(f"Hello, {name}!")

# Using the decorated function
say_hello("Alice")
# Output:
# Something is happening before the function is called.
# Hello, Alice!
# Something is happening after the function is called.
```

Advanced decorators extend this concept by adding parameters to the decorators themselves or implementing them as classes instead of functions, allowing for more complex and reusable behavior modifications.

## 2. Parameterized Decorators

Parameterized decorators are decorators that can accept arguments, allowing you to customize their behavior. The implementation requires an additional layer of nesting: a function that takes the parameters and returns a decorator.

```python
# Parameterized decorator
def repeat(n=3):
    """Decorator that repeats the function execution n times"""
    def decorator(func):
        def wrapper(*args, **kwargs):
            results = []
            for _ in range(n):
                results.append(func(*args, **kwargs))
            return results
        return wrapper
    return decorator

# Using the parameterized decorator
@repeat(n=5)
def greet(name):
    return f"Hello, {name}!"

# Calling the decorated function
print(greet("Bob"))
# Output: ['Hello, Bob!', 'Hello, Bob!', 'Hello, Bob!', 'Hello, Bob!', 'Hello, Bob!']

# Using default parameter
@repeat()  # or simply @repeat
def double(x):
    return x * 2

print(double(10))  # Output: [20, 20, 20]
```

Parameterized decorators enable more flexible and configurable behavior modification of functions.

## 3. Class-based Decorators

Class-based decorators leverage Python's object-oriented features to create more maintainable and stateful decorators. A class decorator must implement the `__call__` method to make instances callable.

```python
class CountCalls:
    """Decorator that counts the number of times a function is called"""
    
    def __init__(self, func):
        self.func = func
        self.count = 0
    
    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"Call {self.count} of {self.func.__name__}")
        return self.func(*args, **kwargs)

@CountCalls
def say_hello(name):
    return f"Hello, {name}!"

# Call the decorated function multiple times
print(say_hello("Alice"))  # Call 1 of say_hello
print(say_hello("Bob"))    # Call 2 of say_hello
print(say_hello("Carol"))  # Call 3 of say_hello

# You can access the state of the decorator
print(f"Function was called {say_hello.count} times")  # Function was called 3 times
```

Class-based decorators with parameters combine the approaches from the previous examples. You need a class that takes parameters and returns a decorator:

```python
class RepeatCalls:
    """Class decorator with parameters"""
    
    def __init__(self, n=3):
        self.n = n
    
    def __call__(self, func):
        def wrapper(*args, **kwargs):
            results = []
            for _ in range(self.n):
                results.append(func(*args, **kwargs))
            return results
        return wrapper

# Using class-based decorator with parameters
@RepeatCalls(n=4)
def greet(name):
    return f"Hi, {name}!"

print(greet("Dave"))  # Output: ['Hi, Dave!', 'Hi, Dave!', 'Hi, Dave!', 'Hi, Dave!']
```

## 4. Preserving Function Metadata

One issue with decorators is that they hide the original function's metadata (like name, docstring, etc.). The `functools.wraps` decorator helps preserve this metadata:

```python
import functools
import time

def timing_decorator(func):
    @functools.wraps(func)  # Preserves metadata of the decorated function
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"{func.__name__} took {end_time - start_time:.6f} seconds to run")
        return result
    return wrapper

@timing_decorator
def slow_function():
    """This function simulates a slow operation"""
    time.sleep(1)
    return "Function completed"

# The function name and docstring are preserved
print(slow_function.__name__)  # Output: slow_function
print(slow_function.__doc__)   # Output: This function simulates a slow operation

# Call the function
print(slow_function())
# Output:
# slow_function took 1.001234 seconds to run
# Function completed
```

## 5. Stacking Multiple Decorators

Decorators can be stacked, with each decorator adding its own behavior. The decorators are applied from bottom to top (the decorator closest to the function is applied first).

```python
def bold(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper

def italic(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper

def underline(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return f"<u>{func(*args, **kwargs)}</u>"
    return wrapper

# Stacking decorators
@bold
@italic
@underline
def greet(name):
    return f"Hello, {name}!"

print(greet("World"))
# Output: <b><i><u>Hello, World!</u></i></b>
```

## 6. Advanced Decorator Patterns

Advanced decorators can implement more complex patterns, such as caching results (memoization), retry logic, or authentication.

### Memoization Decorator

```python
def memoize(func):
    cache = {}
    
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        # Create a key from arguments
        key = str(args) + str(kwargs)
        
        if key not in cache:
            cache[key] = func(*args, **kwargs)
            print(f"Calculated result for {key}")
        else:
            print(f"Using cached result for {key}")
            
        return cache[key]
    
    return wrapper

# Using the memoization decorator
@memoize
def fibonacci(n):
    """Calculate fibonacci number recursively"""
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

print(fibonacci(5))  # Will calculate for 0, 1, 2, 3, 4, 5
print(fibonacci(5))  # Will use cached result
```

### Retry Decorator

```python
import random
import time

def retry(max_attempts=3, delay_seconds=1):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            attempts = 0
            while attempts < max_attempts:
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    attempts += 1
                    if attempts == max_attempts:
                        raise
                    print(f"Attempt {attempts} failed with {e}. Retrying in {delay_seconds} seconds...")
                    time.sleep(delay_seconds)
            return None  # Should never reach here
        return wrapper
    return decorator

# Using the retry decorator
@retry(max_attempts=5, delay_seconds=0.5)
def unstable_function():
    """This function fails randomly"""
    if random.random() < 0.7:  # 70% chance of failure
        raise ConnectionError("Random connection error")
    return "Success!"

try:
    print(unstable_function())
except Exception as e:
    print(f"Function ultimately failed with: {e}")
```

## 7. Real-world Applications

Decorators are used extensively in web frameworks, testing, and other libraries. Here are some examples of how decorators are used in real-world applications:

### Authentication in Web Frameworks

```python
def login_required(func):
    @functools.wraps(func)
    def wrapper(request, *args, **kwargs):
        if not request.user.is_authenticated:
            return redirect('/login/')
        return func(request, *args, **kwargs)
    return wrapper

# In a Flask or Django-like application
@login_required
def protected_view(request):
    return "Welcome, authenticated user!"
```

### Rate Limiting

```python
import time
from collections import deque

class RateLimiter:
    """Decorator class that limits the rate of function calls"""
    
    def __init__(self, max_calls=5, period=60):
        self.max_calls = max_calls
        self.period = period
        self.calls_history = {}  # Dict to track histories for different functions
    
    def __call__(self, func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            # Get or create history for this function
            if func not in self.calls_history:
                self.calls_history[func] = deque()
            
            # Clean up old calls
            current_time = time.time()
            history = self.calls_history[func]
            
            while history and history[0] < current_time - self.period:
                history.popleft()
            
            # Check if we can make a new call
            if len(history) < self.max_calls:
                history.append(current_time)
                return func(*args, **kwargs)
            else:
                oldest_call = history[0]
                wait_time = oldest_call + self.period - current_time
                raise Exception(f"Rate limit exceeded. Try again in {wait_time:.2f} seconds.")
                
        return wrapper

# Using the rate limiter
@RateLimiter(max_calls=3, period=10)
def api_request(endpoint):
    print(f"Making API request to {endpoint}")
    return f"Response from {endpoint}"

# Test the rate limiter
for i in range(5):
    try:
        print(api_request(f"/api/endpoint-{i}"))
    except Exception as e:
        print(f"Error: {e}")
    time.sleep(1)  # Wait 1 second between attempts
```

## 8. Best Practices and Common Pitfalls

### Best Practices

1. **Use `functools.wraps`** to preserve the metadata of decorated functions.
2. **Keep decorators focused** on a single responsibility.
3. **Document your decorators** thoroughly, especially parameterized ones.
4. **Be careful with mutable state** in decorators, especially with class-based ones.
5. **Consider performance implications**, as nested function calls add overhead.

### Common Pitfalls

```python
# Pitfall 1: Forgetting that decorators are executed during import
def print_on_import(func):
    print(f"Importing {func.__name__}")  # This runs during import!
    return func

@print_on_import
def greet():
    return "Hello!"

# Pitfall 2: Decorating methods incorrectly
class WrongDecorator:
    def __init__(self, func):
        self.func = func
    
    def __call__(self, *args, **kwargs):
        # Doesn't handle 'self' properly for methods
        return self.func(*args, **kwargs)

class CorrectDecorator:
    def __init__(self, func):
        self.func = func
    
    def __call__(self, *args, **kwargs):
        return self.func(*args, **kwargs)
    
    def __get__(self, instance, owner):
        # Handle methods properly
        if instance is None:
            return self
        return functools.partial(self, instance)

# Pitfall 3: Capturing arguments incorrectly in parameterized decorators
def buggy_repeat(n):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for _ in range(n):
                # n is captured correctly due to closure
                pass
            
            for i in range(n):
                # But if you redefine or modify a captured variable,
                # it creates a new local variable
                # i = n  # This would break the closure
                pass
            
            return func(*args, **kwargs)
        return wrapper
    return decorator
```

## 9. Summary

Advanced decorators expand Python's metaprogramming capabilities by allowing you to modify function or method behavior in sophisticated ways:

1. **Parameterized decorators** enable configurable behavior through arguments passed to the decorator itself.
2. **Class-based decorators** provide mechanisms for maintaining state between decorator calls and leverage Python's OOP features.
3. **Proper metadata preservation** using `functools.wraps` ensures decorated functions maintain their identity.
4. **Decorator stacking** allows combining multiple behavioral modifications in a clean, layered approach.
5. **Real-world applications** include authentication, rate limiting, memoization, and retry logic, among others.

Mastering advanced decorators unlocks powerful programming patterns that make your code more modular, reusable, and expressive. By understanding both function-based and class-based implementations, you gain flexibility in how you approach different metaprogramming challenges.

When used judiciously, decorators can significantly improve code organization and reduce redundancy. However, they should be employed thoughtfully, with careful attention to readability, documentation, and performance implications.
