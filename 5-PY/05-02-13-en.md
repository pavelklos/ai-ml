## 1. Introduction to Unit Testing

Unit testing is the practice of testing individual components or units of code in isolation to ensure they work as expected. In Python, unit tests help verify that functions, classes, and modules behave correctly, making maintenance and refactoring safer.

Benefits of unit testing include:
- Early detection of bugs
- Documentation of code behavior
- Safer refactoring
- Improved code design
- Regression protection

Let's create a simple function to test:

```python
# sample_code.py
def add(a, b):
    """Add two numbers and return the result."""
    return a + b

def subtract(a, b):
    """Subtract b from a and return the result."""
    return a - b

def multiply(a, b):
    """Multiply two numbers and return the result."""
    return a * b

def divide(a, b):
    """Divide a by b and return the result.
    
    Raises:
        ValueError: If b is 0.
    """
    if b == 0:
        raise ValueError("Cannot divide by zero")
    return a / b
```

## 2. Testing with unittest

Python's built-in `unittest` module provides a framework for organizing and running tests. It's inspired by Java's JUnit and follows an object-oriented approach.

### Basic unittest Structure

```python
# test_calculator_unittest.py
import unittest
from sample_code import add, subtract, multiply, divide

class TestCalculator(unittest.TestCase):
    
    def test_add(self):
        self.assertEqual(add(3, 5), 8)
        self.assertEqual(add(-1, 1), 0)
        self.assertEqual(add(-1, -1), -2)
        
    def test_subtract(self):
        self.assertEqual(subtract(5, 3), 2)
        self.assertEqual(subtract(1, 1), 0)
        self.assertEqual(subtract(-1, -1), 0)
        
    def test_multiply(self):
        self.assertEqual(multiply(3, 5), 15)
        self.assertEqual(multiply(-1, 1), -1)
        self.assertEqual(multiply(-1, -1), 1)
        
    def test_divide(self):
        self.assertEqual(divide(10, 2), 5)
        self.assertEqual(divide(-10, 2), -5)
        self.assertEqual(divide(5, 2), 2.5)
        
    def test_divide_by_zero(self):
        with self.assertRaises(ValueError):
            divide(10, 0)
            
if __name__ == "__main__":
    unittest.main()
```

### Running unittest

You can run unittest in several ways:

```bash
# Run directly
python test_calculator_unittest.py

# Run with unittest module
python -m unittest test_calculator_unittest.py

# Run with test discovery
python -m unittest discover
```

### Common unittest Assertions

```python
# Common assertions
self.assertEqual(a, b)       # a == b
self.assertNotEqual(a, b)    # a != b
self.assertTrue(x)           # bool(x) is True
self.assertFalse(x)          # bool(x) is False
self.assertIs(a, b)          # a is b
self.assertIsNot(a, b)       # a is not b
self.assertIsNone(x)         # x is None
self.assertIsNotNone(x)      # x is not None
self.assertIn(a, b)          # a in b
self.assertNotIn(a, b)       # a not in b
self.assertIsInstance(a, b)  # isinstance(a, b)
self.assertRaises(exc, func, *args, **kwargs)  # func(*args, **kwargs) raises exc
```

## 3. Testing with pytest

`pytest` is a more modern testing framework that offers simpler syntax, powerful fixtures, and extensive plugins.

### Installation

```bash
pip install pytest
```

### Basic pytest Structure

```python
# test_calculator_pytest.py
import pytest
from sample_code import add, subtract, multiply, divide

def test_add():
    assert add(3, 5) == 8
    assert add(-1, 1) == 0
    assert add(-1, -1) == -2
    
def test_subtract():
    assert subtract(5, 3) == 2
    assert subtract(1, 1) == 0
    assert subtract(-1, -1) == 0
    
def test_multiply():
    assert multiply(3, 5) == 15
    assert multiply(-1, 1) == -1
    assert multiply(-1, -1) == 1
    
def test_divide():
    assert divide(10, 2) == 5
    assert divide(-10, 2) == -5
    assert divide(5, 2) == 2.5
    
def test_divide_by_zero():
    with pytest.raises(ValueError):
        divide(10, 0)
```

### Running pytest

```bash
# Run all tests in current directory
pytest

# Run specific test file
pytest test_calculator_pytest.py

# Run with verbose output
pytest -v

# Run tests matching a pattern
pytest -k "add or divide"
```

## 4. Test Fixtures and Setup

Test fixtures provide a way to set up and tear down resources needed for tests.

### unittest Fixtures

```python
# unittest fixtures
import unittest
from sample_code import add, subtract

class TestWithFixtures(unittest.TestCase):
    
    def setUp(self):
        # Called before each test
        print("Setting up test data")
        self.values = [1, 2, 3]
        self.expected_sum = 6
        
    def tearDown(self):
        # Called after each test
        print("Cleaning up")
        self.values = None
        
    def test_sum(self):
        result = 0
        for val in self.values:
            result = add(result, val)
        self.assertEqual(result, self.expected_sum)
        
    @classmethod
    def setUpClass(cls):
        # Called once before all tests
        print("Setting up class")
        
    @classmethod
    def tearDownClass(cls):
        # Called once after all tests
        print("Tearing down class")
```

### pytest Fixtures

```python
# pytest fixtures
import pytest

@pytest.fixture
def values():
    print("Setting up test data")
    values = [1, 2, 3]
    yield values
    print("Cleaning up")
    
def test_sum_with_fixture(values):
    from sample_code import add
    result = 0
    for val in values:
        result = add(result, val)
    assert result == 6
    
# Sharing fixtures across multiple tests
@pytest.fixture(scope="module")
def complex_data():
    print("Setting up complex data")
    data = {"numbers": [1, 2, 3, 4, 5], "expected_sum": 15}
    yield data
    print("Tearing down complex data")
    
def test_complex_sum(complex_data):
    from sample_code import add
    result = 0
    for val in complex_data["numbers"]:
        result = add(result, val)
    assert result == complex_data["expected_sum"]
```

## 5. Mocking and Patching

Mocking allows you to replace parts of your system with mock objects to isolate the code being tested.

### unittest.mock

```python
# service.py
import requests

def get_user_data(user_id):
    response = requests.get(f"https://api.example.com/users/{user_id}")
    if response.status_code == 200:
        return response.json()
    else:
        return None

def get_user_name(user_id):
    data = get_user_data(user_id)
    if data:
        return data.get("name")
    return "Unknown"
```

```python
# test_service_unittest.py
import unittest
from unittest.mock import patch, MagicMock
from service import get_user_name, get_user_data

class TestService(unittest.TestCase):
    
    @patch('service.requests.get')
    def test_get_user_data(self, mock_get):
        # Configure the mock
        mock_response = MagicMock()
        mock_response.status_code = 200
        mock_response.json.return_value = {"id": 1, "name": "John Doe"}
        mock_get.return_value = mock_response
        
        # Call the function
        result = get_user_data(1)
        
        # Assertions
        mock_get.assert_called_once_with("https://api.example.com/users/1")
        self.assertEqual(result, {"id": 1, "name": "John Doe"})
        
    @patch('service.get_user_data')
    def test_get_user_name(self, mock_get_user_data):
        # Configure the mock
        mock_get_user_data.return_value = {"id": 1, "name": "John Doe"}
        
        # Call the function
        result = get_user_name(1)
        
        # Assertions
        self.assertEqual(result, "John Doe")
        mock_get_user_data.assert_called_once_with(1)
        
    @patch('service.get_user_data')
    def test_get_user_name_unknown(self, mock_get_user_data):
        # Configure the mock
        mock_get_user_data.return_value = None
        
        # Call the function
        result = get_user_name(1)
        
        # Assertions
        self.assertEqual(result, "Unknown")
```

### pytest Mocking

```python
# test_service_pytest.py
import pytest
from unittest.mock import patch, MagicMock
from service import get_user_name, get_user_data

def test_get_user_data():
    with patch('service.requests.get') as mock_get:
        # Configure the mock
        mock_response = MagicMock()
        mock_response.status_code = 200
        mock_response.json.return_value = {"id": 1, "name": "John Doe"}
        mock_get.return_value = mock_response
        
        # Call the function
        result = get_user_data(1)
        
        # Assertions
        mock_get.assert_called_once_with("https://api.example.com/users/1")
        assert result == {"id": 1, "name": "John Doe"}

def test_get_user_name(mocker):
    # Using pytest-mock plugin
    mock_get_user_data = mocker.patch('service.get_user_data')
    mock_get_user_data.return_value = {"id": 1, "name": "John Doe"}
    
    result = get_user_name(1)
    
    assert result == "John Doe"
    mock_get_user_data.assert_called_once_with(1)
```

## 6. Parameterized Testing

Parameterized testing allows you to run the same test with different inputs.

### unittest Parameterized Tests

```python
# test_parameterized_unittest.py
import unittest
from sample_code import add

class TestParameterized(unittest.TestCase):
    
    def test_add(self):
        test_cases = [
            (1, 2, 3),
            (5, 3, 8),
            (-1, 1, 0),
            (0, 0, 0)
        ]
        
        for a, b, expected in test_cases:
            with self.subTest(a=a, b=b, expected=expected):
                self.assertEqual(add(a, b), expected)
```

### pytest Parameterized Tests

```python
# test_parameterized_pytest.py
import pytest
from sample_code import add, divide

@pytest.mark.parametrize("a, b, expected", [
    (1, 2, 3),
    (5, 3, 8),
    (-1, 1, 0),
    (0, 0, 0)
])
def test_add_parameterized(a, b, expected):
    assert add(a, b) == expected

# Multiple parameters
@pytest.mark.parametrize("a", [1, 2, 3])
@pytest.mark.parametrize("b", [10, 20])
def test_multiply_combinations(a, b):
    from sample_code import multiply
    result = multiply(a, b)
    assert result == a * b
    
# Parameterized fixture
@pytest.fixture(params=[1, 2, 3, 4, 5])
def input_value(request):
    return request.param

def test_with_parameterized_fixture(input_value):
    assert input_value < 10
```

## 8. Best Practices

Here are some best practices for writing effective unit tests:

### Test Structure

```python
# Follow the AAA pattern: Arrange, Act, Assert
def test_add_follows_aaa_pattern():
    # Arrange
    a, b = 3, 5
    expected = 8
    
    # Act
    result = add(a, b)
    
    # Assert
    assert result == expected
```

### Testing Guidelines

1. **Keep tests simple and focused**: Test one thing per test function
2. **Use descriptive test names**: Make it clear what each test is checking
3. **Isolate tests**: Tests should not depend on each other
4. **Use fixtures for common setup**: Avoid duplicating setup code
5. **Test error cases**: Ensure errors are handled correctly
6. **Use assertions effectively**: Choose the right assertion for each case
7. **Avoid testing implementation details**: Focus on behavior, not internals
8. **Maintain high coverage**: Aim for high test coverage
9. **Test independence**: Tests should run in any order
10. **Write deterministic tests**: Tests should always give the same result

## 9. Summary

Unit testing is a crucial practice in software development that helps ensure code quality and reliability. Python provides two main frameworks for unit testing:

1. **unittest** - The built-in testing framework with an object-oriented approach:
   - Uses test classes that inherit from `unittest.TestCase`
   - Provides various assertion methods
   - Includes test discovery and test runners

2. **pytest** - A more modern and feature-rich testing framework:
   - Simpler syntax with plain functions and assertions
   - Powerful fixtures for setup and teardown
   - Extensive plugin ecosystem
   - Parameterized testing support
   - Better reporting and output

Key testing concepts covered:
- Test fixtures for setup and teardown
- Mocking to isolate code under test
- Parameterized tests to test multiple scenarios
- Test coverage to ensure thorough testing
- Best practices for writing maintainable tests

By incorporating unit testing into your development workflow, you can catch bugs early, document expected behavior, and build more reliable software. Whether you choose unittest or pytest (or a combination of both), the important thing is to write tests consistently and make testing an integral part of your development process.
