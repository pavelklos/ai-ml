## 1. Základy struktury projektu

Dobře organizovaný Python projekt usnadňuje jeho pochopení, údržbu a spolupráci. Zde je základní struktura, která funguje pro většinu projektů:

```
project_name/
│
├── project_name/       # Hlavní adresář balíčku
│   ├── __init__.py     # Činí adresář balíčkem
│   ├── main.py         # Hlavní aplikační modul
│   ├── utils.py        # Užitečné funkce
│   └── config.py       # Konfigurační nastavení
│
├── tests/              # Adresář pro testy
│   ├── __init__.py
│   └── test_main.py    # Testy pro main.py
│
├── docs/               # Dokumentace
│   └── README.md       # Dokumentace projektu
│
├── .gitignore          # Git ignore soubor
├── requirements.txt    # Závislosti projektu
├── setup.py            # Instalační skript balíčku
└── README.md           # Přehled projektu
```

Tato struktura odděluje kód, testy a dokumentaci, což činí projekt přehlednějším.

## 2. Vytvoření základního Python balíčku

Pro vytvoření správného Python balíčku potřebujete soubor `__init__.py` a skript `setup.py`:

```python
# project_name/__init__.py
"""
Hlavní balíček pro project_name.

Tento balíček poskytuje funkcionalitu pro...
"""

__version__ = '0.1.0'
```

Soubor `setup.py` definuje, jak by měl být váš balíček nainstalován:

```python
# setup.py
from setuptools import setup, find_packages

setup(
    name="project_name",
    version="0.1.0",
    packages=find_packages(),
    install_requires=[
        "requests>=2.25.0",
        "pandas>=1.2.0",
    ],
    author="Vaše Jméno",
    author_email="vas.email@example.com",
    description="Krátký popis vašeho projektu",
    long_description=open("README.md").read(),
    long_description_content_type="text/markdown",
    url="https://github.com/vaseuzivatelsekjmeno/project_name",
    classifiers=[
        "Programming Language :: Python :: 3",
        "License :: OSI Approved :: MIT License",
        "Operating System :: OS Independent",
    ],
    python_requires=">=3.6",
)
```

Pro lokální instalaci balíčku pro vývoj:

```bash
pip install -e .
```

## 3. Správa závislostí

Závislosti by měly být jasně definovány, aby byl váš projekt reprodukovatelný. Vytvořte soubor requirements.txt:

```
# requirements.txt
requests>=2.25.0
pandas>=1.2.0
pytest>=6.2.0
sphinx>=3.4.0
```

Pro složitější projekty zvažte použití samostatných souborů pro různá prostředí:

```
requirements/
├── base.txt       # Základní závislosti
├── dev.txt        # Vývojářské nástroje
└── prod.txt       # Závislosti specifické pro produkci
```

Příklad `dev.txt`:

```
-r base.txt
pytest>=6.2.0
pytest-cov>=2.10.0
black>=20.8b1
flake8>=3.8.4
```

Závislosti můžete také definovat v `setup.py` pomocí parametru `install_requires`, jak bylo uvedeno výše.

## 4. Správa konfigurace

Oddělte konfiguraci od kódu, aby byla vaše aplikace flexibilnější:

```python
# project_name/config.py
"""Konfigurační nastavení pro projekt."""

import os
from pathlib import Path

# Základní adresář projektu
BASE_DIR = Path(__file__).resolve().parent.parent

# Výchozí konfigurace
DEFAULT_CONFIG = {
    "api_url": "https://api.example.com",
    "timeout": 30,
    "max_retries": 3,
    "log_level": "INFO",
}

# Konfigurace specifická pro prostředí
def get_config():
    """
    Načte a vrátí konfiguraci.
    
    Proměnné prostředí přepisují výchozí nastavení.
    """
    config = DEFAULT_CONFIG.copy()
    
    # Přepsání proměnnými prostředí
    if os.environ.get("API_URL"):
        config["api_url"] = os.environ["API_URL"]
    
    if os.environ.get("TIMEOUT"):
        config["timeout"] = int(os.environ["TIMEOUT"])
    
    if os.environ.get("MAX_RETRIES"):
        config["max_retries"] = int(os.environ["MAX_RETRIES"])
    
    if os.environ.get("LOG_LEVEL"):
        config["log_level"] = os.environ["LOG_LEVEL"]
        
    return config

# Přístup ke konfiguraci
config = get_config()
```

Pro složitější konfigurace zvažte použití externích konfiguračních souborů (YAML, JSON, INI) nebo specializovaných knihoven jako `python-decouple` nebo `dynaconf`.

## 5. Organizace kódu pomocí modulů

S růstem projektu organizujte související funkce do samostatných modulů:

```
project_name/
├── __init__.py
├── main.py
├── api/
│   ├── __init__.py
│   ├── client.py
│   └── models.py
├── db/
│   ├── __init__.py
│   ├── connection.py
│   └── models.py
└── utils/
    ├── __init__.py
    ├── helpers.py
    └── validation.py
```

Příklad organizace kódu:

```python
# project_name/api/client.py
"""API klient pro externí služby."""

import requests
from ..config import config

class APIClient:
    """Klient pro interakci s externí API."""
    
    def __init__(self, base_url=None, timeout=None):
        self.base_url = base_url or config["api_url"]
        self.timeout = timeout or config["timeout"]
        
    def get_data(self, endpoint):
        """Získá data z API endpointu."""
        url = f"{self.base_url}/{endpoint}"
        response = requests.get(url, timeout=self.timeout)
        response.raise_for_status()
        return response.json()
```

Poté můžete tento modul importovat a používat:

```python
# project_name/main.py
"""Hlavní aplikační modul."""

from .api.client import APIClient

def fetch_user_data(user_id):
    """Získá data pro konkrétního uživatele."""
    client = APIClient()
    return client.get_data(f"users/{user_id}")

def main():
    """Hlavní vstupní bod."""
    user_data = fetch_user_data(42)
    print(f"Uživatelská data: {user_data}")

if __name__ == "__main__":
    main()
```

## 6. Osvědčené postupy pro dokumentaci

Dobrá dokumentace je zásadní pro každý projekt. Zahrňte:

1. README.md - Přehled projektu
2. Docstringy - Pro moduly, třídy, funkce
3. API dokumentaci - Vygenerovanou z docstringů
4. Příklady a návody

Příklad README.md:

```markdown
# Název projektu

Stručný popis toho, co projekt dělá.

## Instalace

```bash
pip install project_name
```

## Použití

```python
from project_name import main

výsledek = main.process_data("input.txt")
print(výsledek)
```

## Vývoj

1. Naklonujte repozitář
2. Nainstalujte vývojové závislosti: `pip install -e ".[dev]"`
3. Spusťte testy: `pytest`

## Licence

MIT
```

Pro komplexní API dokumentaci zvažte použití Sphinx:

```python
# docs/conf.py
project = 'project_name'
copyright = '2023, Vaše Jméno'
author = 'Vaše Jméno'

extensions = [
    'sphinx.ext.autodoc',
    'sphinx.ext.viewcode',
    'sphinx.ext.napoleon',
]

html_theme = 'sphinx_rtd_theme'
```

## 8. Struktura testování

Organizujte testy tak, aby odrážely strukturu vašeho balíčku:

```
tests/
├── __init__.py
├── test_main.py
├── api/
│   ├── __init__.py
│   ├── test_client.py
│   └── test_models.py
└── utils/
    ├── __init__.py
    ├── test_helpers.py
    └── test_validation.py
```

Příklad testovacího souboru pomocí pytest:

```python
# tests/api/test_client.py
"""Testy pro modul API klienta."""

import pytest
from unittest.mock import patch, MagicMock
from project_name.api.client import APIClient

def test_api_client_initialization():
    """Test inicializace APIClient s výchozími hodnotami."""
    client = APIClient()
    assert client.base_url == "https://api.example.com"
    assert client.timeout == 30
    
    # Test s vlastními hodnotami
    custom_client = APIClient(base_url="https://custom.api.com", timeout=60)
    assert custom_client.base_url == "https://custom.api.com"
    assert custom_client.timeout == 60

@patch("project_name.api.client.requests.get")
def test_get_data_success(mock_get):
    """Test úspěšného získání API dat."""
    # Konfigurace mocku
    mock_response = MagicMock()
    mock_response.json.return_value = {"id": 1, "name": "Test User"}
    mock_response.raise_for_status.return_value = None
    mock_get.return_value = mock_response
    
    # Volání metody
    client = APIClient()
    result = client.get_data("users/1")
    
    # Tvrzení
    assert result == {"id": 1, "name": "Test User"}
    mock_get.assert_called_once_with(
        "https://api.example.com/users/1", 
        timeout=30
    )
```

Přidejte soubor `pytest.ini` nebo `setup.cfg` pro konfiguraci pytest:

```ini
# pytest.ini
[pytest]
testpaths = tests
python_files = test_*.py
python_functions = test_*
python_classes = Test*
addopts = --verbose --cov=project_name
```

## 9. Návrh rozhraní příkazového řádku

Pokud váš projekt zahrnuje rozhraní příkazového řádku, použijte `argparse` nebo `click` k jeho čistému implementování:

Příklad s `argparse`:

```python
# project_name/cli.py
"""Rozhraní příkazového řádku pro project_name."""

import argparse
import sys
from . import main

def parse_args(args=None):
    """Parsování argumentů příkazového řádku."""
    parser = argparse.ArgumentParser(
        description="Popis rozhraní příkazového řádku vašeho projektu"
    )
    
    parser.add_argument(
        "input_file",
        help="Cesta k vstupnímu souboru"
    )
    
    parser.add_argument(
        "-o", "--output",
        help="Cesta k výstupnímu souboru (výchozí: stdout)",
        default=None
    )
    
    parser.add_argument(
        "--verbose",
        action="store_true",
        help="Povolit podrobný výstup"
    )
    
    return parser.parse_args(args)

def cli_main(args=None):
    """Hlavní vstupní bod pro CLI."""
    args = parse_args(args)
    
    try:
        result = main.process_data(args.input_file, verbose=args.verbose)
        
        if args.output:
            with open(args.output, 'w') as f:
                f.write(str(result))
        else:
            print(result)
        
        return 0
    except Exception as e:
        print(f"Chyba: {e}", file=sys.stderr)
        return 1

if __name__ == "__main__":
    sys.exit(cli_main())
```

Pak můžete v `setup.py` definovat vstupní body:

```python
# setup.py
# ... další argumenty setup
entry_points={
    'console_scripts': [
        'project-name=project_name.cli:cli_main',
    ],
},
```

To umožňuje uživatelům spustit váš program pouze pomocí `project-name [argumenty]` po instalaci.

## 10. Shrnutí

Dobrá organizace Python projektu se řídí těmito klíčovými principy:

1. **Konzistentní struktura**: Používejte standardní rozložení projektu, aby byl váš kód přehlednější.
2. **Správné balíčkování**: Vytvářejte instalovatelné balíčky pomocí souborů `setup.py` a `__init__.py`.
3. **Správa závislostí**: Jasně specifikujte požadavky pro reprodukovatelnost.
4. **Oddělení konfigurace**: Udržujte konfiguraci oddělenou od kódu.
5. **Modulární návrh**: Organizujte kód do logických modulů s růstem projektů.
6. **Komplexní dokumentace**: Zahrnujte README, docstringy a API dokumentaci.
7. **Integrace se správou verzí**: Nastavte správné soubory pro ignorování a šablony.
8. **Organizace testů**: Strukturujte testy tak, aby odrážely váš balíček.
9. **Uživatelsky přívětivé CLI**: Navrhněte čistá rozhraní příkazového řádku, pokud je to potřeba.

Dodržování těchto postupů učiní vaše projekty lépe udržovatelnými, znovupoužitelnými a vhodnými pro spolupráci. S růstem projektů zvažte pokročilejší techniky jako kontinuální integrace, automatizované nasazení nebo architektury mikroslužeb, ale tyto základní principy vám dobře poslouží v projektech jakékoliv velikosti.
