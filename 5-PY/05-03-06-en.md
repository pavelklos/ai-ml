## 1. Introduction to Type Hints

Type hints were introduced in Python 3.5 through PEP 484, allowing developers to indicate the expected types of variables, function parameters, and return values. While Python remains dynamically typed, type hints provide several benefits:

- Improved code readability and self-documentation
- Better IDE support (auto-completion, error detection)
- Static type checking to catch type-related errors before runtime
- Enhanced refactoring capabilities

Type hints don't affect Python's runtime behavior by default - they're just hints for tools, IDEs, and developers.

```python
# Without type hints
def calculate_total(price, quantity):
    return price * quantity

# With type hints
def calculate_total(price: float, quantity: int) -> float:
    return price * quantity
```

## 2. Basic Type Annotations

The most basic type hints are applied to variables using the colon syntax:

```python
# Basic type annotations
name: str = "John Doe"
age: int = 30
height: float = 1.75
is_active: bool = True

# The annotation can be added without initializing
employee_id: int  # No value assigned yet
employee_id = 12345

# Type hints for constants (by convention, use Final)
from typing import Final
MAX_CONNECTIONS: Final[int] = 100
```

Python's built-in types can be directly used as annotations, including `str`, `int`, `float`, `bool`, `bytes`, and `complex`.

## 3. Collection Type Hints

For collections, we use types from the `typing` module to specify what types the collection will contain:

```python
from typing import List, Dict, Set, Tuple, Sequence

# Lists
numbers: List[int] = [1, 2, 3, 4, 5]
names: List[str] = ["Alice", "Bob", "Charlie"]

# Dictionaries
user_ages: Dict[str, int] = {"Alice": 30, "Bob": 25}
config: Dict[str, str] = {"host": "localhost", "port": "8000"}

# Sets
unique_ids: Set[int] = {1, 2, 3, 4, 5}

# Tuples with fixed size
point: Tuple[float, float] = (10.5, 20.5)

# Tuples with variable size
numbers: Tuple[int, ...] = (1, 2, 3, 4, 5)

# Sequences (list-like objects)
items: Sequence[str] = ["apple", "banana", "cherry"]

# In Python 3.9+, you can use built-in collection types directly
modern_numbers: list[int] = [1, 2, 3, 4, 5]  # Python 3.9+
modern_ages: dict[str, int] = {"Alice": 30, "Bob": 25}  # Python 3.9+
```

## 4. Function and Return Type Annotations

Type hints are particularly useful for documenting function parameters and return values:

```python
from typing import List, Dict, Optional

def greet(name: str) -> str:
    return f"Hello, {name}!"

def calculate_average(numbers: List[float]) -> float:
    if not numbers:
        return 0.0
    return sum(numbers) / len(numbers)

def process_data(data: Dict[str, int], scale: float = 1.0) -> Dict[str, float]:
    result: Dict[str, float] = {}
    for key, value in data.items():
        result[key] = value * scale
    return result

# Functions that don't return a value
def log_message(message: str) -> None:
    print(f"LOG: {message}")

# Multiple parameters with different types
def register_user(username: str, age: int, active: bool = True) -> Dict[str, object]:
    return {"username": username, "age": age, "active": active}
```

## 5. Union Types and Optional Values

Sometimes a variable or parameter can accept multiple types. For this, we use `Union` or the shorthand `|` operator (Python 3.10+):

```python
from typing import Union, Optional

# A variable that can be either an int or a string
user_id: Union[int, str] = 123
user_id = "ABC123"  # Also valid

# In Python 3.10+, you can use the | operator
price: int | float = 19.99

# Optional is a shorthand for Union[X, None]
# These two are equivalent:
def get_user(user_id: Optional[int] = None) -> Dict[str, object]:
    if user_id is None:
        return {"id": 0, "name": "Guest"}
    # Lookup user by ID
    return {"id": user_id, "name": f"User {user_id}"}

def get_config(path: Union[str, None] = None) -> Dict[str, str]:
    if path is None:
        path = "default_config.json"
    # Load config from path
    return {"setting": "value"}

# In Python 3.10+, you can simply write:
def get_items(category: str | None = None) -> list[str]:
    if category is None:
        return ["item1", "item2"]
    # Return items filtered by category
    return [f"{category}_item1", f"{category}_item2"]
```

## 6. Type Aliases and Custom Types

Type aliases allow you to create custom names for complex types, improving readability:

```python
from typing import Dict, List, Tuple, TypedDict, NewType

# Simple type aliases
UserId = int
Point = Tuple[float, float]
Points = List[Point]

def plot_points(points: Points) -> None:
    for point in points:
        x, y = point
        print(f"Plotting point ({x}, {y})")

# You can use these aliases anywhere
user_id: UserId = 42
coordinates: Point = (10.5, 20.5)
path: Points = [(0.0, 0.0), (1.0, 1.0), (2.0, 0.5)]

# For structured dictionaries, you can use TypedDict
class UserDict(TypedDict):
    id: int
    name: str
    email: str
    active: bool

def process_user(user: UserDict) -> None:
    print(f"Processing {user['name']}, ID: {user['id']}")

valid_user: UserDict = {
    "id": 123,
    "name": "John Doe",
    "email": "john@example.com",
    "active": True
}

# NewType creates distinct types
EmployeeId = NewType("EmployeeId", int)

def get_employee_details(employee_id: EmployeeId) -> Dict[str, object]:
    # Fetch employee details
    return {"name": "Employee Name"}

regular_id = 123
employee_id = EmployeeId(regular_id)  # Convert to EmployeeId
get_employee_details(employee_id)  # Valid
# get_employee_details(regular_id)  # Type checkers will flag this as an error
```

## 7. Generic Types

Generics allow you to define reusable components that work with multiple types:

```python
from typing import TypeVar, Generic, List, Dict

# Define a type variable
T = TypeVar('T')
K = TypeVar('K')
V = TypeVar('V')

# Generic function example
def first_element(collection: List[T]) -> T:
    if not collection:
        raise IndexError("Empty collection")
    return collection[0]

# Usage
first_int = first_element([1, 2, 3])  # Type: int
first_str = first_element(["a", "b", "c"])  # Type: str

# Generic class example
class Stack(Generic[T]):
    def __init__(self) -> None:
        self.items: List[T] = []
        
    def push(self, item: T) -> None:
        self.items.append(item)
        
    def pop(self) -> T:
        if not self.items:
            raise IndexError("Pop from an empty stack")
        return self.items.pop()
    
    def peek(self) -> T:
        if not self.items:
            raise IndexError("Peek from an empty stack")
        return self.items[-1]
    
    def is_empty(self) -> bool:
        return len(self.items) == 0

# Usage
int_stack = Stack[int]()
int_stack.push(1)
int_stack.push(2)
print(int_stack.pop())  # 2

str_stack = Stack[str]()
str_stack.push("hello")
print(str_stack.peek())  # "hello"

# Generic dictionary class
class KeyValueStore(Generic[K, V]):
    def __init__(self) -> None:
        self.store: Dict[K, V] = {}
    
    def set(self, key: K, value: V) -> None:
        self.store[key] = value
    
    def get(self, key: K) -> V:
        return self.store[key]

# Usage
str_to_int = KeyValueStore[str, int]()
str_to_int.set("one", 1)
str_to_int.set("two", 2)
print(str_to_int.get("one"))  # 1
```

## 8. Static Type Checking with mypy

Mypy is a static type checker for Python that can catch type-related errors before runtime:

```python
# example.py
def add(a: int, b: int) -> int:
    return a + b

# This would cause a type error when checked with mypy
result = add("hello", "world")
```

To check your code with mypy:

```bash
pip install mypy
mypy example.py
```

Output:
```
example.py:5: error: Argument 1 to "add" has incompatible type "str"; expected "int"
example.py:5: error: Argument 2 to "add" has incompatible type "str"; expected "int"
```

Configuration can be added to a `mypy.ini` file:

```ini
# mypy.ini
[mypy]
python_version = 3.10
warn_return_any = True
warn_unused_configs = True
disallow_untyped_defs = True
disallow_incomplete_defs = True

[mypy.plugins.numpy.*]
follow_imports = silent
```

Common mypy flags to enforce stricter checking:

```python
# Use strict mode with @mypy.stubgen
from typing import Any, List

# Without this flag, mypy would allow this function without type annotations
def untyped_func(a, b):  # mypy error with disallow_untyped_defs
    return a + b

# Incomplete type annotations
def incomplete_func(a: int, b):  # mypy error with disallow_incomplete_defs
    return a + b

# Any type allows for less strict checking
def process_data(data: Any) -> None:  # mypy warning with warn_return_any
    print(data)
```

## 9. Runtime Type Checking

Sometimes you might want to enforce type checking at runtime:

```python
from typing import List, Dict, Any, cast, TypeGuard
import inspect

# Simple runtime type checking
def enforce_types(func):
    signature = inspect.signature(func)
    parameters = signature.parameters
    
    def wrapper(*args, **kwargs):
        bound_arguments = signature.bind(*args, **kwargs)
        bound_arguments.apply_defaults()
        
        for param_name, param_value in bound_arguments.arguments.items():
            if param_name in parameters:
                param_type = parameters[param_name].annotation
                if param_type is not inspect.Parameter.empty and not isinstance(param_value, param_type):
                    raise TypeError(f"Parameter '{param_name}' must be of type {param_type.__name__}")
        
        result = func(*args, **kwargs)
        return_type = signature.return_annotation
        
        if return_type is not inspect.Signature.empty and not isinstance(result, return_type):
            raise TypeError(f"Return value must be of type {return_type.__name__}")
        
        return result
    
    return wrapper

# Using the runtime type checker
@enforce_types
def add_numbers(a: int, b: int) -> int:
    return a + b

# This will raise a TypeError at runtime
try:
    add_numbers(1, "2")
except TypeError as e:
    print(e)  # Parameter 'b' must be of type int

# For more robust runtime type checking, use libraries like:
# - pydantic
# - typeguard
# - beartype
```

For production use, consider libraries specifically designed for runtime type checking:

```python
# Using typeguard for runtime type checking
from typeguard import typechecked

@typechecked
def process_user_data(user_id: int, settings: Dict[str, bool]) -> List[str]:
    return [f"Setting: {k}" for k, v in settings.items() if v]

# This will raise a runtime error
# process_user_data("123", {"notify": True})  # TypeError: type of argument "user_id" must be int; got str instead
```

## 10. Best Practices and Limitations

### Best Practices

```python
# 1. Be consistent with type annotations
def inconsistent(a: int, b):  # Bad: mix of annotated and non-annotated
    return a + b

def consistent(a: int, b: int) -> int:  # Good: all parameters annotated
    return a + b

# 2. Use None instead of Optional for default parameters
# Bad
def bad_optional(value: Optional[int] = None) -> int:
    return value if value is not None else 0

# Good
def good_optional(value: int | None = None) -> int:
    return value if value is not None else 0

# 3. Use Protocol for duck typing
from typing import Protocol, Iterable

class Drawable(Protocol):
    def draw(self) -> None: ...

def draw_all(items: Iterable[Drawable]) -> None:
    for item in items:
        item.draw()

class Circle:
    def draw(self) -> None:
        print("Drawing a circle")

class Square:
    def draw(self) -> None:
        print("Drawing a square")

draw_all([Circle(), Square()])  # Works without inheritance

# 4. Use Literal for constrained string/number options
from typing import Literal

def align_text(alignment: Literal["left", "center", "right"]) -> str:
    return f"Text aligned {alignment}"

align_text("left")     # OK
align_text("center")   # OK
# align_text("top")    # Type error
```

### Limitations

Type hints have some limitations to be aware of:

```python
# 1. Runtime overhead - type hints don't affect runtime behavior
def calculate(a: int, b: int) -> int:
    return a + b

calculate("hello", "world")  # Works at runtime: "helloworld"

# 2. Dynamic features can be hard to type correctly
def dynamic_attributes(obj: object) -> None:
    # Hard to type hint when using dynamic attributes
    obj.dynamic_attr = "value"  # Type checkers might complain

# 3. Complex type relationships
from typing import TypeVar, cast

T = TypeVar('T')
def complex_relationship(x: T) -> T:
    # Some complex logic where the type relationship
    # is hard to express with Python's type system
    result = do_something_with(x)
    return cast(T, result)  # Sometimes we need to use cast

# 4. Third-party libraries without type hints
import some_library  # If this library doesn't have type hints

result = some_library.function()  # Type will be Any
```

## Summary

Type hinting in Python provides a powerful way to document code and catch errors before runtime:

1. **Type annotations** add clarity and improve IDE support without affecting runtime behavior
2. **Collection types** allow specifying the types of elements in data structures
3. **Function annotations** document the expected inputs and outputs of functions
4. **Union and Optional types** enable flexible handling of different possible types
5. **Type aliases and custom types** improve code readability and organization
6. **Generic types** enable type-safe reusable components
7. **Static type checking with mypy** catches type errors before execution
8. **Runtime type checking** can verify types during program execution
9. **Best practices** include being consistent and using appropriate typing constructs
10. **Limitations** include runtime overhead and challenges with dynamic features

By incorporating type hints into your Python code, you can create more maintainable, self-documenting code that's less prone to bugs and easier to refactor.
