## 1. Úvod do virtuálních prostředí

Virtuální prostředí jsou izolovaná prostředí Pythonu, která vám umožňují instalovat balíčky pro konkrétní projekty bez ovlivnění celkové instalace Pythonu v systému. Pomáhají vám efektivně spravovat závislosti, vyhnout se konfliktům verzí mezi projekty a usnadňují reprodukovatelnost vašich projektů.

```python
# Proč používat virtuální prostředí?

# Problém: Různé projekty mohou vyžadovat různé verze balíčků
# Projekt A potřebuje package_x verzi 1.0
# Projekt B potřebuje package_x verzi 2.0

# Bez virtuálních prostředí:
# - Můžete mít nainstalovanou pouze jednu verzi současně
# - Aktualizace balíčků pro jeden projekt může rozbít jiný
# - Systémový Python se může zaplnit balíčky
# - Těžko se sledují přesné závislosti pro projekt

# S virtuálními prostředími:
# - Každý projekt má své vlastní izolované prostředí
# - Různé projekty mohou používat různé verze balíčků
# - Závislosti jsou jasně definovány pro každý projekt
# - Projekty lze snadno sdílet s přesným nastavením prostředí
```

## 2. Vytváření a nastavení virtuálních prostředí

Python nabízí několik nástrojů pro vytváření virtuálních prostředí. Vestavěný modul `venv` je standardním přístupem pro Python 3.3+ a je doporučen pro většinu uživatelů.

```python
# Použití vestavěného modulu venv (Python 3.3+)

# Vytvoření nového virtuálního prostředí
# Windows
# python -m venv moje_prostredi

# macOS/Linux
# python3 -m venv moje_prostredi

# Aktivace virtuálního prostředí
# Windows
# moje_prostredi\Scripts\activate

# macOS/Linux
# source moje_prostredi/bin/activate

# Příkazový řádek by měl nyní zobrazovat název prostředí
# (moje_prostredi) $

# Deaktivace prostředí po dokončení
# deactivate

# Použití virtualenv (alternativa, funguje i s Pythonem 2)
# Nejprve jej nainstalujte:
# pip install virtualenv

# Poté vytvořte virtuální prostředí:
# virtualenv moje_prostredi

# Aktivace je stejná jako s venv
```

## 3. Správa balíčků Pythonu ve virtuálních prostředích

Jakmile je vaše virtuální prostředí aktivováno, můžete instalovat, aktualizovat a odstraňovat balíčky bez ovlivnění jiných prostředí nebo globální instalace Pythonu.

```python
# Ujistěte se, že vaše virtuální prostředí je nejprve aktivováno
# (moje_prostredi) $

# Instalace balíčků
# pip install numpy

# Instalace konkrétních verzí
# pip install pandas==1.3.0

# Aktualizace balíčků
# pip install --upgrade matplotlib

# Výpis nainstalovaných balíčků
# pip list

# Získání podrobných informací o balíčku
# pip show requests

# Instalace více balíčků najednou
# pip install numpy pandas matplotlib seaborn

# Odinstalace balíčků
# pip uninstall requests

# Kontrola cesty Pythonu (potvrzuje, že používáte virtuální prostředí)
import sys
print(sys.executable)  # Mělo by ukazovat na Python ve vašem virtuálním prostředí
print(sys.prefix)      # Mělo by zobrazovat cestu k vašemu virtuálnímu prostředí
```

## 4. Práce se soubory requirements

Soubory requirements vám umožňují definovat všechny závislosti projektu v jednom souboru, což usnadňuje opětovné vytvoření prostředí na jiných systémech nebo sdílení s kolegy.

```python
# Generování souboru requirements z aktuálního prostředí
# pip freeze > requirements.txt

# Příklad souboru requirements.txt:
# numpy==1.20.3
# pandas==1.3.0
# matplotlib==3.4.2
# requests>=2.25.1

# Instalace všech balíčků ze souboru requirements
# pip install -r requirements.txt

# Ruční vytvoření minimálního souboru requirements
# with open('requirements.txt', 'w') as f:
#     f.write('numpy>=1.20.0\n')
#     f.write('pandas>=1.3.0\n')
#     f.write('matplotlib>=3.4.0\n')

# Kontrola, zda jsou všechny požadavky nainstalovány
import pkg_resources
import sys

def zkontroluj_pozadavky(soubor_pozadavku):
    """Zkontroluje, zda jsou splněny všechny požadavky."""
    with open(soubor_pozadavku, 'r') as f:
        pozadavky = [radek.strip() for radek in f if radek.strip() and not radek.startswith('#')]
    
    for pozadavek in pozadavky:
        try:
            pkg_resources.require(pozadavek)
            print(f"✓ {pozadavek}")
        except pkg_resources.DistributionNotFound:
            print(f"✗ {pozadavek} nenalezen")
        except pkg_resources.VersionConflict as e:
            print(f"✗ {pozadavek} konflikt verzí: {e}")

# Použití:
# zkontroluj_pozadavky('requirements.txt')
```

## 5. Pracovní postupy projektů s virtuálními prostředími

Typický pracovní postup při zahájení nového projektu v Pythonu s použitím virtuálních prostředí.

```python
# Krok 1: Vytvoření nového adresáře projektu
# mkdir muj_novy_projekt
# cd muj_novy_projekt

# Krok 2: Vytvoření virtuálního prostředí
# python -m venv venv

# Krok 3: Aktivace prostředí
# source venv/bin/activate  # Na Windows: venv\Scripts\activate

# Krok 4: Instalace potřebných balíčků
# pip install pandas matplotlib

# Krok 5: Začátek práce na projektu
# Vytvoření jednoduchého skriptu
with open('analyza.py', 'w') as f:
    f.write("""
import pandas as pd
import matplotlib.pyplot as plt

# Vzorová data
data = {'Rok': [2018, 2019, 2020, 2021, 2022],
        'Prodej': [150, 200, 180, 310, 340]}

df = pd.DataFrame(data)
print(df)

# Vytvoření jednoduchého grafu
plt.figure(figsize=(10, 6))
plt.plot(df['Rok'], df['Prodej'], marker='o')
plt.title('Roční prodeje')
plt.xlabel('Rok')
plt.ylabel('Prodej')
plt.grid(True)
plt.savefig('trend_prodeje.png')
plt.show()
""")

# Krok 6: Vygenerování souboru requirements
# pip freeze > requirements.txt

# Krok 7: Po dokončení deaktivace prostředí
# deactivate
```

## 6. Porovnání nástrojů pro virtuální prostředí

Pro správu virtuálních prostředí v Pythonu existuje několik nástrojů. Zde jsou ty nejběžnější:

```python
# 1. venv (vestavěný v Pythonu 3.3+)
# Výhody: Vestavěný, není potřeba další instalace, jednoduchý na použití
# Nevýhody: Není dostupný v Pythonu 2.x, méně funkcí než alternativy
# Použití: python -m venv moje_prostredi

# 2. virtualenv
# Výhody: Funguje s Pythonem 2 i 3, více funkcí než venv
# Nevýhody: Vyžaduje samostatnou instalaci
# Použití: virtualenv moje_prostredi
# Instalace: pip install virtualenv

# 3. conda (Anaconda/Miniconda)
# Výhody: Může spravovat nepythonové závislosti, dobrý pro data science
# Nevýhody: Těžší, samostatný ekosystém od pip
# Použití: conda create -n moje_prostredi python=3.9
# Aktivace: conda activate moje_prostredi

# 4. pipenv
# Výhody: Kombinuje pip a virtualenv, řeší závislosti
# Nevýhody: Odlišný pracovní postup, může být pomalejší
# Použití: pipenv install requests
# Instalace: pip install pipenv

# 5. poetry
# Výhody: Moderní správa závislostí, balení v jednom nástroji
# Nevýhody: Odlišný pracovní postup než tradiční nástroje, křivka učení
# Použití: poetry new muj_projekt
# Instalace: pip install poetry

# Příklad výběru mezi nástroji:
def doporuc_nastroj_prostredi(verze_pythonu, je_data_science, potreba_reprodukovatelnosti):
    if verze_pythonu < 3:
        print("Pro Python 2.x: Použijte virtualenv")
    elif je_data_science:
        print("Pro projekty data science: Zvažte condu")
    elif potreba_reprodukovatelnosti:
        print("Pro vysoce reprodukovatelné projekty: Zvažte poetry nebo pipenv")
    else:
        print("Pro standardní projekty Pythonu 3: Použijte vestavěný venv")
```

## 7. Osvědčené postupy pro virtuální prostředí

Dodržování těchto osvědčených postupů vám pomůže efektivně spravovat vaše virtuální prostředí.

```python
# 1. Nikdy neukládejte adresáře virtuálních prostředí do systému správy verzí
# Vytvořte soubor .gitignore:
with open('.gitignore', 'w') as f:
    f.write("""
# Adresáře virtuálních prostředí
venv/
env/
.env/
.venv/
ENV/
*.pyc
__pycache__/

# Distribuce / balení
dist/
build/
*.egg-info/
""")

# 2. Vždy zahrnujte soubor requirements.txt nebo podobný soubor závislostí
# pip freeze > requirements.txt

# 3. Pojmenovávejte svá prostředí konzistentně
# Pro projektově specifická prostředí:
# python -m venv .venv  # Skrytá složka v adresáři projektu

# 4. Dokumentujte nastavení prostředí v README
with open('README.md', 'w') as f:
    f.write("""
# Můj Projekt

## Nastavení

1. Vytvořte virtuální prostředí:
   ```
   python -m venv venv
   ```

2. Aktivujte virtuální prostředí:
   - Windows: `venv\\Scripts\\activate`
   - macOS/Linux: `source venv/bin/activate`

3. Nainstalujte závislosti:
   ```
   pip install -r requirements.txt
   ```

4. Spusťte aplikaci:
   ```
   python app.py
   ```
""")

# 5. Používejte konzistentní metodu aktivace
# Vytvořte aktivační skript pro váš tým
with open('aktivovat_prostredi.py', 'w') as f:
    f.write("""
import os
import platform
import subprocess
import sys

def aktivovat_prostredi():
    env_dir = '.venv'
    if not os.path.exists(env_dir):
        print(f"Vytvářím virtuální prostředí v {env_dir}...")
        subprocess.check_call([sys.executable, '-m', 'venv', env_dir])
    
    if platform.system() == 'Windows':
        print("Pro aktivaci spusťte:")
        print(f"{env_dir}\\\\Scripts\\\\activate")
    else:
        print("Pro aktivaci spusťte:")
        print(f"source {env_dir}/bin/activate")
    
    print("\\nPoté nainstalujte požadavky pomocí:")
    print("pip install -r requirements.txt")

if __name__ == '__main__':
    aktivovat_prostredi()
""")
```

## 8. Shrnutí

Virtuální prostředí jsou nezbytným nástrojem při vývoji v Pythonu, poskytující izolované prostory pro závislosti vašich projektů. Klíčové body k zapamatování:

- Virtuální prostředí řeší konflikty závislostí mezi projekty
- Vestavěný modul `venv` v Pythonu je standardním způsobem, jak vytvářet prostředí
- Každé virtuální prostředí má svůj vlastní interpret Pythonu a instalace balíčků
- Soubory requirements pomáhají učinit prostředí reprodukovatelnými
- Vždy aktivujte své prostředí před instalací balíčků nebo spuštěním kódu
- Nikdy neukládejte složky virtuálních prostředí do systému správy verzí
- Různé nástroje (venv, virtualenv, conda, pipenv, poetry) nabízejí různé funkce pro různé případy použití
- Typický pracovní postup zahrnuje vytvoření, aktivaci, instalaci balíčků a generování souborů requirements

Zvládnutí virtuálních prostředí je klíčovou dovedností pro vývojáře Pythonu, která činí vaše projekty udržitelnějšími, sdílitelnějšími a reprodukovatelnějšími.
