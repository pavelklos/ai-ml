## 1. Introduction to Decorators

Decorators are a powerful feature in Python that allows you to modify or enhance functions and methods without changing their source code. They are based on the concept of functions being first-class objects in Python, which means functions can be passed as arguments, returned from other functions, and assigned to variables.

```python
# In Python, functions are first-class objects
def greet(name):
    return f"Hello, {name}!"

# Functions can be assigned to variables
say_hi = greet
print(say_hi("Alice"))  # Output: Hello, Alice!

# Functions can be passed as arguments
def apply_function(func, value):
    return func(value)

print(apply_function(greet, "Bob"))  # Output: Hello, Bob!

# Functions can return other functions
def create_greeting_function(greeting):
    def greet_person(name):
        return f"{greeting}, {name}!"
    return greet_person

say_good_morning = create_greeting_function("Good morning")
print(say_good_morning("Charlie"))  # Output: Good morning, Charlie!
```

Decorators leverage these concepts to wrap a function with another function, modifying its behavior or adding additional functionality.

## 2. Basic Decorator Syntax

A decorator is a function that takes another function as an argument, extends its behavior, and returns the modified function. The basic syntax uses the `@` symbol placed above the function definition.

```python
# A simple decorator
def my_decorator(func):
    def wrapper():
        print("Something is happening before the function is called.")
        func()
        print("Something is happening after the function is called.")
    return wrapper

# Using the decorator with @ syntax
@my_decorator
def say_hello():
    print("Hello!")

# This is equivalent to:
# say_hello = my_decorator(say_hello)

# Call the decorated function
say_hello()
```

Output:
```
Something is happening before the function is called.
Hello!
Something is happening after the function is called.
```

Decorators that accept functions with arguments:

```python
def my_decorator(func):
    def wrapper(*args, **kwargs):
        print(f"Function {func.__name__} is being called with {args} and {kwargs}")
        result = func(*args, **kwargs)
        print(f"Function {func.__name__} finished execution")
        return result
    return wrapper

@my_decorator
def add(a, b):
    return a + b

result = add(5, 3)
print(f"Result: {result}")
```

Output:
```
Function add is being called with (5, 3) and {}
Function add finished execution
Result: 8
```

## 3. Function Wrappers with functools.wraps

When creating decorators, the wrapper function replaces the original function. This can cause issues with introspection because the metadata of the original function (like name, docstring) is lost. The `functools.wraps` decorator helps preserve this metadata.

```python
import functools

def my_decorator(func):
    @functools.wraps(func)  # Preserves metadata of the original function
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@my_decorator
def display_info(name, age):
    """Display information about a person."""
    print(f"{name} is {age} years old")

# Without functools.wraps, these would show the wrapper's info
print(display_info.__name__)  # Output: display_info (not "wrapper")
print(display_info.__doc__)   # Output: Display information about a person.

# Call the function
display_info("David", 30)
```

Output:
```
display_info
Display information about a person.
Calling display_info
David is 30 years old
```

## 4. Decorators with Arguments

You can create decorators that accept arguments by adding another level of function nesting:

```python
def repeat(n=1):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            results = []
            for _ in range(n):
                results.append(func(*args, **kwargs))
            return results
        return wrapper
    return decorator

@repeat(n=3)
def greet(name):
    return f"Hello, {name}!"

print(greet("Emily"))
```

Output:
```
['Hello, Emily!', 'Hello, Emily!', 'Hello, Emily!']
```

## 5. Class-based Decorators

Decorators can also be implemented as classes by using the `__call__` method, which makes an object callable like a function:

```python
class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)
        self.func = func
        self.count = 0
        
    def __call__(self, *args, **kwargs):
        self.count += 1
        print(f"Call {self.count} to {self.func.__name__}")
        return self.func(*args, **kwargs)

@CountCalls
def say_hello(name):
    return f"Hello, {name}!"

print(say_hello("Frank"))
print(say_hello("Grace"))
print(say_hello("Helen"))
```

Output:
```
Call 1 to say_hello
Hello, Frank!
Call 2 to say_hello
Hello, Grace!
Call 3 to say_hello
Hello, Helen!
```

## 6. Multiple Decorators

You can apply multiple decorators to a single function. They are applied from bottom to top (the decorator closest to the function is applied first):

```python
def bold(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper

def italic(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper

@bold
@italic
def format_text(text):
    return text

# This is equivalent to:
# format_text = bold(italic(format_text))

print(format_text("Hello, World!"))
```

Output:
```
<b><i>Hello, World!</i></b>
```

## 7. Practical Applications

Decorators have many practical uses in real-world Python programming:

### Timing Functions

```python
import time

def timer(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        result = func(*args, **kwargs)
        end_time = time.time()
        print(f"Function {func.__name__} took {end_time - start_time:.4f} seconds to run")
        return result
    return wrapper

@timer
def slow_function():
    time.sleep(1)
    return "Done processing"

slow_function()
```

### Authentication and Authorization

```python
def require_auth(func):
    @functools.wraps(func)
    def wrapper(user, *args, **kwargs):
        if not user.is_authenticated:
            raise PermissionError("Authentication required")
        return func(user, *args, **kwargs)
    return wrapper

class User:
    def __init__(self, name, is_authenticated=False):
        self.name = name
        self.is_authenticated = is_authenticated

@require_auth
def view_protected_resource(user):
    return f"Welcome, {user.name}! Here's your protected data."

# Test with an unauthenticated user
try:
    user = User("John", is_authenticated=False)
    print(view_protected_resource(user))
except PermissionError as e:
    print(f"Error: {e}")

# Test with an authenticated user
user = User("John", is_authenticated=True)
print(view_protected_resource(user))
```

### Caching Results (Memoization)

```python
def memoize(func):
    cache = {}
    
    @functools.wraps(func)
    def wrapper(*args):
        if args not in cache:
            cache[args] = func(*args)
            print(f"Calculated result for {args}")
        else:
            print(f"Using cached result for {args}")
        return cache[args]
    
    return wrapper

@memoize
def fibonacci(n):
    if n < 2:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

print(fibonacci(10))  # Calculate all values
print(fibonacci(10))  # Use cached result
```

## 8. Common Patterns and Best Practices

### Templated Decorators

Creating a template for building similar decorators:

```python
def create_decorator(before_message, after_message):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            print(before_message)
            result = func(*args, **kwargs)
            print(after_message)
            return result
        return wrapper
    return decorator

# Create specific decorators
log_entry_exit = create_decorator("Entering function", "Exiting function")
debug_calls = create_decorator("Debug: function call", "Debug: function completed")

@log_entry_exit
def process_data(data):
    print(f"Processing {data}...")
    return f"Processed: {data}"

@debug_calls
def analyze(data):
    print(f"Analyzing {data}...")
    return f"Analysis results for {data}"

print(process_data("customer records"))
print()
print(analyze("sales figures"))
```

### Best Practices

1. **Always use `functools.wraps`** to preserve the metadata of the decorated function.
2. **Keep decorators simple** - they should follow the Single Responsibility Principle.
3. **Handle exceptions properly** - don't let your decorators swallow exceptions.
4. **Document how decorators modify function behavior** in docstrings.

```python
def log_exceptions(func):
    """
    A decorator that logs exceptions raised by the decorated function.
    
    Args:
        func: The function to decorate
        
    Returns:
        A wrapper function that logs exceptions
    """
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        try:
            return func(*args, **kwargs)
        except Exception as e:
            print(f"Exception in {func.__name__}: {e}")
            raise  # Re-raise the exception after logging
    return wrapper

@log_exceptions
def divide(a, b):
    """Divide a by b and return the result."""
    return a / b

try:
    print(divide(10, 0))
except ZeroDivisionError:
    print("Caught division error in main code")
```

## 9. Debugging Decorated Functions

Debugging decorated functions can be challenging because you're adding layers of indirection. Here are some techniques:

```python
def debug_decorator(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        args_repr = [repr(a) for a in args]
        kwargs_repr = [f"{k}={v!r}" for k, v in kwargs.items()]
        signature = ", ".join(args_repr + kwargs_repr)
        print(f"Calling {func.__name__}({signature})")
        
        result = func(*args, **kwargs)
        
        print(f"{func.__name__} returned {result!r}")
        return result
    return wrapper

@debug_decorator
def calculate_total(items, tax_rate=0.1):
    total = sum(items)
    return total * (1 + tax_rate)

calculate_total([10, 20, 30], tax_rate=0.05)
```

Another technique is to provide a way to disable decorators during debugging:

```python
def debug_decorator(active=True):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            if active:
                print(f"Calling {func.__name__}")
                result = func(*args, **kwargs)
                print(f"{func.__name__} returned {result}")
                return result
            else:
                # Skip the decoration if not active
                return func(*args, **kwargs)
        return wrapper
    return decorator

# Debugging can be toggled
DEBUG = False  # Set to True to enable debugging

@debug_decorator(active=DEBUG)
def multiply(a, b):
    return a * b

print(multiply(4, 5))  # No debug output when DEBUG is False
```

## 10. Summary

Decorators are a powerful feature in Python that enables:

1. **Code reuse** - Apply common behaviors to multiple functions
2. **Separation of concerns** - Keep core functionality separate from auxiliary behavior
3. **Clean, readable code** - Apply cross-cutting functionality without cluttering function bodies

Key concepts to remember:

- A decorator is a function that takes a function and returns an enhanced function
- The `@decorator` syntax is syntactic sugar for `function = decorator(function)`
- Use `functools.wraps` to preserve function metadata
- Decorators can take arguments by adding another level of function nesting
- Class-based decorators implement the `__call__` method
- Multiple decorators are applied from bottom to top
- Common use cases include timing, authentication, logging, and caching

Decorators exemplify Python's flexibility and philosophy of clean, reusable code. By understanding and applying decorators effectively, you can write more maintainable and elegant Python programs.
