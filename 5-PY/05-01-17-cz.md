## 1. Úvod do ladění

Ladění (debugging) je proces hledání a opravování chyb (bugů) ve vašem kódu. Je to základní dovednost pro každého programátora. Python nabízí několik nástrojů a technik, které vám pomohou efektivně ladit váš kód.

```python
# Funkce s potenciální chybou
def calculate_average(numbers):
    total = 0
    for num in numbers:
        total += num
    return total / len(numbers)  # Potenciální dělení nulou, pokud je numbers prázdný

# Toto způsobí chybu
try:
    result = calculate_average([])
    print(f"Průměr je {result}")
except Exception as e:
    print(f"Došlo k chybě: {e}")
    # Výstup: Došlo k chybě: division by zero
```

Ladění nám pomáhá identifikovat problémy, jako je ten výše uvedený (dělení nulou), a opravit je dříve, než způsobí problémy v produkčním kódu.

## 2. Použití příkazů print

Nejjednodušší technikou ladění je přidání příkazů print do vašeho kódu pro sledování hodnot proměnných, průběhu provádění a potenciálních problémů.

```python
def calculate_average(numbers):
    print(f"Přijatý vstup: {numbers}")  # Vytiskne vstup pro ladění
    
    total = 0
    for i, num in enumerate(numbers):
        total += num
        print(f"Po přidání {num}: total = {total}")  # Sleduje průběžný součet
    
    print(f"Konečný součet: {total}, počet: {len(numbers)}")  # Kontrola před výsledkem
    
    # Ochrana proti dělení nulou
    if len(numbers) == 0:
        print("Chyba: Nelze vypočítat průměr prázdného seznamu")
        return 0
    
    result = total / len(numbers)
    print(f"Vypočítaný průměr: {result}")  # Vytiskne konečný výsledek
    return result

# Test s platným vstupem
calculate_average([1, 2, 3, 4, 5])

# Test s prázdným vstupem
calculate_average([])
```

I když je jednoduchý, ladění pomocí příkazů print má omezení:
- Zanáší váš kód
- Musí být ručně přidán a odstraněn
- Neumožňuje interaktivní zkoumání stavu programu

## 3. Vestavěný debugger Pythonu (pdb)

Vestavěný debugger Pythonu (pdb) umožňuje interaktivní ladění. Můžete zkoumat proměnné, procházet kód krok za krokem a vyhodnocovat výrazy za běhu.

```python
import pdb

def complex_calculation(a, b, c):
    result1 = a * b
    pdb.set_trace()  # Provedení se zde zastaví a vstoupí do interaktivního režimu ladění
    result2 = result1 / c
    return result2

# Když spustíte tuto funkci
complex_calculation(10, 5, 0)

# V interaktivní relaci pdb můžete:
# - Napsat 'p result1' pro vytisknutí hodnoty result1
# - Napsat 'p c' a uvidíte, že c je 0
# - Napsat 'q' pro ukončení debuggeru
# - Napsat 'n' pro další řádek
# - Napsat 'c' pro pokračování provádění až k dalšímu breakpointu
# - Napsat 'h' pro nápovědu k dostupným příkazům
```

Základní příkazy pdb:
- `n` (next): Provede aktuální řádek a přesune se na další
- `s` (step): Vstoupí do volání funkce
- `c` (continue): Pokračuje v provádění, dokud nenarazí na breakpoint
- `p výraz` (print): Vyhodnotí a vytiskne výraz
- `l` (list): Zobrazí aktuální řádek a okolní kód
- `q` (quit): Ukončí debugger

## 4. Použití funkce breakpoint()

Python 3.7+ představil vestavěnou funkci `breakpoint()`, která je pohodlnějším způsobem, jak vstoupit do debuggeru.

```python
def divide_numbers(a, b):
    result = a / b
    breakpoint()  # Python zde pozastaví provádění
    return result

# Spuštění této funkce
divide_numbers(10, 2)  # Funguje dobře
divide_numbers(10, 0)  # Způsobí chybu, ale můžete zkoumat stav před jejím výskytem

# Ve výchozím nastavení breakpoint() používá pdb, ale můžete jej nakonfigurovat pomocí proměnných prostředí
# Nastavte PYTHONBREAKPOINT=0 pro úplné zakázání breakpointů
# Nastavte PYTHONBREAKPOINT=module.function pro použití vlastní ladící funkce
```

Výhodou `breakpoint()` je, že můžete snadno povolit/zakázat všechny breakpointy nastavením proměnné prostředí `PYTHONBREAKPOINT`, což je výhodné pro nasazení do produkčního prostředí.

## 5. Zpracování výjimek pro ladění

Strategické použití bloků try-except může pomoci diagnostikovat problémy poskytnutím více informací o výjimkách.

```python
def process_data(data):
    try:
        result = {}
        for key, value in data.items():
            # Pokus o normalizaci a zpracování každé hodnoty
            try:
                processed_value = value / sum(data.values())
                result[key] = processed_value
            except Exception as e:
                print(f"Chyba při zpracování klíče '{key}' s hodnotou {value}: {e}")
                # Pokračuje s dalšími položkami místo pádu
        return result
    except Exception as e:
        print(f"Fatální chyba v process_data: {e}")
        print(f"Vstupní data byla: {data}")
        # Znovu vyvolá nebo vrátí výchozí hodnotu
        raise

# Testovací případy
try:
    print(process_data({"a": 10, "b": 20, "c": 30}))  # Mělo by fungovat
    print(process_data({"a": 0, "b": 0, "c": 0}))     # Dělení nulou
    print(process_data(123))                          # Není slovník
except Exception as e:
    print(f"Zachyceno na nejvyšší úrovni: {e}")
```

Zpracování výjimek jako technika ladění vám pomáhá:
- Identifikovat, která část kódu selhává
- Pochopit kontext, ve kterém chyby nastávají
- Udržet váš program v chodu navzdory chybám (kde je to vhodné)
- Shromažďovat diagnostiku pro složité chyby

## 6. Protokolování pro ladění

Modul `logging` poskytuje sofistikovanější alternativu k příkazům print, s úrovněmi závažnosti a možnostmi konfigurace.

```python
import logging

# Konfigurace protokolování
logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    filename='debug.log'  # Volitelné: zápis do souboru místo konzole
)

def calculate_statistics(numbers):
    logging.debug(f"calculate_statistics voláno s {numbers}")
    
    if not numbers:
        logging.warning("Prázdný seznam poskytnutý funkci calculate_statistics")
        return 0, 0
    
    try:
        average = sum(numbers) / len(numbers)
        logging.info(f"Vypočítaný průměr: {average}")
        
        variance = sum((x - average) ** 2 for x in numbers) / len(numbers)
        logging.debug(f"Mezivýsledek výpočtu variance: {variance}")
        
        std_dev = variance ** 0.5
        logging.info(f"Vypočítaná směrodatná odchylka: {std_dev}")
        
        return average, std_dev
    except Exception as e:
        logging.error(f"Chyba v calculate_statistics: {e}", exc_info=True)
        raise

# Test funkce
calculate_statistics([1, 2, 3, 4, 5])
calculate_statistics([])
```

Výhody protokolování oproti příkazům print:
- Lze povolit/zakázat bez změny kódu
- Různé úrovně závažnosti (DEBUG, INFO, WARNING, ERROR, CRITICAL)
- Může zahrnovat časová razítka a informace o zdroji
- Může posílat výstup do různých cílů (konzole, soubory, síťové služby)
- Zůstává užitečné v produkčním prostředí

## 7. Ladění pomocí tvrzení (assertions)

Tvrzení (assertions) jsou příkazy, které kontrolují, zda je podmínka pravdivá, a pokud není, vyvolají výjimku. Jsou užitečné pro detekci programátorských chyb a ověřování předpokladů.

```python
def calculate_discount(price, discount_percentage):
    # Zajistí platnost vstupů
    assert price >= 0, f"Cena nemůže být záporná: {price}"
    assert 0 <= discount_percentage <= 100, f"Sleva musí být mezi 0 a 100: {discount_percentage}"
    
    # Výpočet ceny po slevě
    discount = price * (discount_percentage / 100)
    final_price = price - discount
    
    # Ověří, že výsledek dává smysl
    assert final_price <= price, f"Cena po slevě ({final_price}) by měla být nižší než původní ({price})"
    
    return final_price

# Test funkce
try:
    print(calculate_discount(100, 20))   # Mělo by fungovat: 80.0
    print(calculate_discount(100, 150))  # Měl by selhat assert: sleva > 100%
except AssertionError as e:
    print(f"Assertion selhal: {e}")
```

Tvrzení jsou užitečná pro:
- Dokumentování a vynucování předpokladů funkce (prekondice a postkondice)
- Včasné zachycení programátorských chyb ve vývoji
- Samotestující kód

Poznámka: Tvrzení lze v optimalizovaném režimu zakázat (s příznakem `-O`), proto je nepoužívejte pro kód, který musí běžet v produkci.

## 8. Nástroje pro ladění v IDE

Moderní IDE jako PyCharm, VS Code a Spyder poskytují grafická rozhraní pro ladění, která činí ladění intuitivnějším a výkonnějším.

```python
# Příklad kódu k ladění v IDE
def fibonacci(n):
    """Vypočítá n-té Fibonacciho číslo."""
    if n <= 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fibonacci(n-1) + fibonacci(n-2)

def calculate_fibonacci_ratio(n):
    """Vypočítá poměr po sobě jdoucích Fibonacciho čísel."""
    if n <= 1:
        return 1
    
    fib_n = fibonacci(n)
    fib_n_minus_1 = fibonacci(n-1)
    
    return fib_n / fib_n_minus_1

# Pokus o výpočet a vytisknutí poměrů
for i in range(10):
    ratio = calculate_fibonacci_ratio(i)
    print(f"F({i})/F({i-1}) = {ratio}")
```

V IDE můžete:
- Nastavit breakpointy kliknutím na okraj vedle čísel řádků
- Procházet provádění kódu řádek po řádku
- Zkoumat a upravovat hodnoty proměnných během provádění
- Zobrazit zásobník volání, abyste pochopili, jak jste se dostali do aktuálního bodu
- Vyhodnocovat výrazy v aktuálním kontextu
- Nastavit podmíněné breakpointy, které se aktivují pouze když je splněna určitá podmínka

## 9. Běžné chyby a jak je najít

Znalost nejběžnějších chyb vám může pomoci ladit efektivněji.

```python
# 1. Chyby o jedničku (off-by-one errors)
def print_first_n(items, n):
    # Chyba: Toto vytiskne n+1 položek
    for i in range(n + 1):  # Mělo by být range(n)
        print(items[i])

# 2. Nesprávné odsazení
def is_even(number):
    if number % 2 == 0:
        result = True
    else:
        result = False
    return result  # Toto funguje, ale pokud by bylo odsazeno pod else, vracelo by hodnotu pouze při lichých číslech

# 3. Měnitelné výchozí argumenty
def add_to_list(item, my_list=[]):  # Chyba: Výchozí seznam je vytvořen pouze jednou
    my_list.append(item)
    return my_list

print(add_to_list(1))  # [1]
print(add_to_list(2))  # [1, 2] - Není nový seznam!

# 4. Překlepy v názvech proměnných
count = 0
for i in range(10):
    coutn = count + i  # Chyba: Překlep v názvu proměnné vytváří novou proměnnou

# 5. Chybějící příkaz return
def calculate_total(prices):
    total = sum(prices)
    # Chybí return total

# Strategie ladění těchto běžných chyb:
# - Pro off-by-one chyby: Zkontrolujte hranice smyček a testujte s malými vstupy
# - Pro odsazení: Použijte IDE s řádným zvýrazňováním odsazení
# - Pro měnitelné výchozí hodnoty: Použijte None jako výchozí hodnotu a vytvořte měnitelný objekt v těle funkce
# - Pro překlepy: Povolte linting ve vašem IDE
# - Pro chybějící return: Přidejte ladící výpisy nebo použijte debugger pro sledování provádění
```

## 10. Shrnutí a osvědčené postupy

Efektivní ladění v Pythonu kombinuje více technik podle situace.

Osvědčené postupy pro ladění Python kódu:

```python
def demonstrate_best_practices():
    """Funkce k demonstraci osvědčených postupů ladění."""
    
    # 1. Začněte s jasným porozuměním očekávaného chování
    expected_output = 15
    
    # 2. Používejte popisné názvy proměnných
    input_values = [1, 2, 3, 4, 5]
    
    # 3. Rozdělte složité operace na menší kroky
    partial_sum = sum(input_values)
    final_result = partial_sum
    
    # 4. Přidejte kontroly platnosti
    assert len(input_values) > 0, "Vstupní seznam nemůže být prázdný"
    
    # 5. Používejte protokolování pro důležité informace
    import logging
    logging.info(f"Zpracovávám {len(input_values)} hodnot")
    
    # 6. Zpracovávejte výjimky s konkrétními chybovými zprávami
    try:
        average = final_result / len(input_values)
    except ZeroDivisionError:
        logging.error("Nelze vypočítat průměr prázdného seznamu")
        average = 0
    
    # 7. Ověřte, že výsledky odpovídají očekáváním
    if average != expected_output / len(input_values):
        logging.warning(f"Neočekávaný výsledek: získáno {average}, očekáváno {expected_output / len(input_values)}")
    
    return final_result

# Pamatujte:
# - Začněte s nejjednoduššími metodami ladění (příkazy print) před složitějšími
# - Izolujte problémy testováním jednotlivých komponent
# - Vytvářejte minimální reprodukovatelné příklady, když hledáte pomoc
# - Používejte verzovací systém pro sledování změn během ladění
# - Naučte se číst a chápat chybové zprávy a trasování
```

Shrnutím lze říci, že ladění je kritickou dovedností pro vývojáře v Pythonu. Začít s jednoduchými technikami jako jsou příkazy print a postupně přecházet k sofistikovanějším nástrojům jako pdb, protokolování a debuggery v IDE vás učiní efektivnějšími při hledání a opravování chyb. Pamatujte, že k ladění přistupujte metodicky, izolujte problémy a důkladně testujte vaše opravy.
