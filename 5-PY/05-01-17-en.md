## 1. Introduction to Debugging

Debugging is the process of finding and fixing errors (bugs) in your code. It's an essential skill for any programmer. Python provides several tools and techniques to help you debug your code efficiently.

```python
# A function with a potential bug
def calculate_average(numbers):
    total = 0
    for num in numbers:
        total += num
    return total / len(numbers)  # Potential division by zero if numbers is empty

# This will cause an error
try:
    result = calculate_average([])
    print(f"The average is {result}")
except Exception as e:
    print(f"An error occurred: {e}")
    # Output: An error occurred: division by zero
```

Debugging helps us identify issues like the one above (division by zero) and fix them before they cause problems in production code.

## 2. Using Print Statements

The simplest debugging technique is adding print statements to your code to track variable values, execution flow, and potential issues.

```python
def calculate_average(numbers):
    print(f"Input received: {numbers}")  # Print input for debugging
    
    total = 0
    for i, num in enumerate(numbers):
        total += num
        print(f"After adding {num}: total = {total}")  # Track running sum
    
    print(f"Final total: {total}, count: {len(numbers)}")  # Pre-result check
    
    # Guard against division by zero
    if len(numbers) == 0:
        print("Error: Cannot calculate average of empty list")
        return 0
    
    result = total / len(numbers)
    print(f"Calculated average: {result}")  # Print final result
    return result

# Test with valid input
calculate_average([1, 2, 3, 4, 5])

# Test with empty input
calculate_average([])
```

While simple, print statement debugging has limitations:
- Clutters your code
- Must be manually added and removed
- Doesn't allow interactive inspection of program state

## 3. Python's Built-in Debugger (pdb)

Python's built-in debugger (pdb) allows for interactive debugging. You can inspect variables, step through code, and evaluate expressions at runtime.

```python
import pdb

def complex_calculation(a, b, c):
    result1 = a * b
    pdb.set_trace()  # Execution stops here and enters interactive debugging mode
    result2 = result1 / c
    return result2

# When you run this function
complex_calculation(10, 5, 0)

# In the pdb interactive session you can:
# - Type 'p result1' to print the value of result1
# - Type 'p c' to see that c is 0
# - Type 'q' to quit the debugger
# - Type 'n' for next line
# - Type 'c' to continue execution until next breakpoint
# - Type 'h' for help on available commands
```

Basic pdb commands:
- `n` (next): Execute the current line and move to the next one
- `s` (step): Step into a function call
- `c` (continue): Continue execution until a breakpoint is hit
- `p expression` (print): Evaluate and print an expression
- `l` (list): Show the current line and surrounding code
- `q` (quit): Exit the debugger

## 4. Using the Breakpoint() Function

Python 3.7+ introduced the built-in `breakpoint()` function, which is a more convenient way to drop into the debugger.

```python
def divide_numbers(a, b):
    result = a / b
    breakpoint()  # Python will pause execution here
    return result

# Running this function
divide_numbers(10, 2)  # Works fine
divide_numbers(10, 0)  # Will cause an error, but you can examine state before it happens

# By default, breakpoint() uses pdb, but you can configure it with environment variables
# Set PYTHONBREAKPOINT=0 to disable breakpoints completely
# Set PYTHONBREAKPOINT=module.function to use a custom debugging function
```

The advantage of `breakpoint()` is that you can easily enable/disable all breakpoints by setting the `PYTHONBREAKPOINT` environment variable, making it convenient for deployment environments.

## 5. Exception Handling for Debugging

Strategic use of try-except blocks can help diagnose problems by providing more information about exceptions.

```python
def process_data(data):
    try:
        result = {}
        for key, value in data.items():
            # Try to normalize and process each value
            try:
                processed_value = value / sum(data.values())
                result[key] = processed_value
            except Exception as e:
                print(f"Error processing key '{key}' with value {value}: {e}")
                # Continue with other items instead of crashing
        return result
    except Exception as e:
        print(f"Fatal error in process_data: {e}")
        print(f"Input data was: {data}")
        # Re-raise or return a default
        raise

# Test cases
try:
    print(process_data({"a": 10, "b": 20, "c": 30}))  # Should work
    print(process_data({"a": 0, "b": 0, "c": 0}))     # Division by zero
    print(process_data(123))                          # Not a dictionary
except Exception as e:
    print(f"Caught at top level: {e}")
```

Exception handling as a debugging technique helps you:
- Identify which part of the code is failing
- Understand the context in which errors occur
- Keep your program running despite errors (where appropriate)
- Collect diagnostics for complex bugs

## 6. Logging for Debugging

The `logging` module provides a more sophisticated alternative to print statements, with levels of severity and configuration options.

```python
import logging

# Configure logging
logging.basicConfig(
    level=logging.DEBUG,
    format='%(asctime)s - %(name)s - %(levelname)s - %(message)s',
    filename='debug.log'  # Optional: write to file instead of console
)

def calculate_statistics(numbers):
    logging.debug(f"calculate_statistics called with {numbers}")
    
    if not numbers:
        logging.warning("Empty list provided to calculate_statistics")
        return 0, 0
    
    try:
        average = sum(numbers) / len(numbers)
        logging.info(f"Calculated average: {average}")
        
        variance = sum((x - average) ** 2 for x in numbers) / len(numbers)
        logging.debug(f"Intermediate variance calculation: {variance}")
        
        std_dev = variance ** 0.5
        logging.info(f"Calculated standard deviation: {std_dev}")
        
        return average, std_dev
    except Exception as e:
        logging.error(f"Error in calculate_statistics: {e}", exc_info=True)
        raise

# Test the function
calculate_statistics([1, 2, 3, 4, 5])
calculate_statistics([])
```

Benefits of logging over print statements:
- Can be enabled/disabled without changing code
- Different severity levels (DEBUG, INFO, WARNING, ERROR, CRITICAL)
- Can include timestamps and source information
- Can output to different destinations (console, files, network services)
- Remains useful in production environments

## 7. Debugging with Assertions

Assertions are statements that check if a condition is true and raise an exception if it's not. They're useful for detecting programming errors and validating assumptions.

```python
def calculate_discount(price, discount_percentage):
    # Ensure inputs are valid
    assert price >= 0, f"Price cannot be negative: {price}"
    assert 0 <= discount_percentage <= 100, f"Discount must be between 0 and 100: {discount_percentage}"
    
    # Calculate discounted price
    discount = price * (discount_percentage / 100)
    final_price = price - discount
    
    # Verify the result makes sense
    assert final_price <= price, f"Discounted price ({final_price}) should be less than original ({price})"
    
    return final_price

# Test the function
try:
    print(calculate_discount(100, 20))   # Should work: 80.0
    print(calculate_discount(100, 150))  # Should assert: discount > 100%
except AssertionError as e:
    print(f"Assertion failed: {e}")
```

Assertions are useful for:
- Documenting and enforcing function preconditions and postconditions
- Catching programming errors early in development
- Self-testing code

Note: Assertions can be disabled in optimized mode (with the `-O` flag), so don't use them for code that must run in production.

## 8. IDE Debugging Tools

Modern IDEs like PyCharm, VS Code, and Spyder provide graphical debugging interfaces that make debugging more intuitive and powerful.

```python
# Example code to debug in an IDE
def fibonacci(n):
    """Calculate the nth Fibonacci number."""
    if n <= 0:
        return 0
    elif n == 1:
        return 1
    else:
        return fibonacci(n-1) + fibonacci(n-2)

def calculate_fibonacci_ratio(n):
    """Calculate the ratio of consecutive Fibonacci numbers."""
    if n <= 1:
        return 1
    
    fib_n = fibonacci(n)
    fib_n_minus_1 = fibonacci(n-1)
    
    return fib_n / fib_n_minus_1

# Try to calculate and print ratios
for i in range(10):
    ratio = calculate_fibonacci_ratio(i)
    print(f"F({i})/F({i-1}) = {ratio}")
```

In IDEs, you can:
- Set breakpoints by clicking in the margin next to line numbers
- Step through code execution line by line
- Inspect and modify variable values during execution
- View the call stack to understand how you reached the current point
- Evaluate expressions in the current context
- Set conditional breakpoints that only trigger when a specified condition is true

## 9. Common Bugs and How to Find Them

Knowing the most common bugs can help you debug more efficiently.

```python
# 1. Off-by-one errors
def print_first_n(items, n):
    # Bug: This prints n+1 items
    for i in range(n + 1):  # Should be range(n)
        print(items[i])

# 2. Incorrect indentation
def is_even(number):
    if number % 2 == 0:
        result = True
    else:
        result = False
    return result  # This works, but if indented under else, would only return on odd numbers

# 3. Mutable default arguments
def add_to_list(item, my_list=[]):  # Bug: Default list is created once
    my_list.append(item)
    return my_list

print(add_to_list(1))  # [1]
print(add_to_list(2))  # [1, 2] - Not a new list!

# 4. Variable name typos
count = 0
for i in range(10):
    coutn = count + i  # Bug: Typo in variable name creates a new variable

# 5. Missing return statement
def calculate_total(prices):
    total = sum(prices)
    # Missing return total

# Debugging strategies for these common bugs:
# - For off-by-one errors: Check loop boundaries and test with small inputs
# - For indentation: Use an IDE with proper indentation highlighting
# - For mutable defaults: Use None as default and create mutable in function body
# - For typos: Enable linting in your IDE
# - For missing returns: Add debug prints or use a debugger to trace execution
```

## 10. Summary and Best Practices

Effective debugging in Python combines multiple techniques based on the situation.

Best practices for debugging Python code:

```python
def demonstrate_best_practices():
    """Function to demonstrate debugging best practices."""
    
    # 1. Start with a clear understanding of expected behavior
    expected_output = 15
    
    # 2. Use descriptive variable names
    input_values = [1, 2, 3, 4, 5]
    
    # 3. Break complex operations into smaller steps
    partial_sum = sum(input_values)
    final_result = partial_sum
    
    # 4. Add validation checks
    assert len(input_values) > 0, "Input list cannot be empty"
    
    # 5. Use logging for important information
    import logging
    logging.info(f"Processing {len(input_values)} values")
    
    # 6. Handle exceptions with specific error messages
    try:
        average = final_result / len(input_values)
    except ZeroDivisionError:
        logging.error("Cannot calculate average of empty list")
        average = 0
    
    # 7. Verify results match expectations
    if average != expected_output / len(input_values):
        logging.warning(f"Unexpected result: got {average}, expected {expected_output / len(input_values)}")
    
    return final_result

# Remember:
# - Start with simplest debugging methods (print statements) before complex ones
# - Isolate problems by testing individual components
# - Create minimal reproducible examples when seeking help
# - Use version control to track changes during debugging
# - Learn to read and understand error messages and tracebacks
```

In summary, debugging is a critical skill for Python developers. Starting with simple techniques like print statements and gradually moving to more sophisticated tools like pdb, logging, and IDE debuggers will make you more efficient at finding and fixing bugs. Remember to approach debugging methodically, isolate problems, and test your fixes thoroughly.
