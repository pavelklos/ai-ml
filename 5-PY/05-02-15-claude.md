# Python Closures and Scopes

## 1. Understanding Variable Scopes in Python

In Python, a variable's scope determines where in your code the variable can be accessed. Python has several levels of scope:

- **Local scope**: Variables defined within a function
- **Enclosing scope**: Variables in the outer function when dealing with nested functions
- **Global scope**: Variables defined at the top level of a module or explicitly declared global
- **Built-in scope**: Names that are pre-defined in Python

Let's examine how these scopes work:

```python
# Built-in scope (print, len, etc.)
# Global scope
x = 100

def outer_function():
    # Enclosing scope relative to inner_function
    y = 200
    
    def inner_function():
        # Local scope
        z = 300
        print(f"Inside inner_function: x={x}, y={y}, z={z}")
    
    inner_function()
    print(f"Inside outer_function: x={x}, y={y}")
    # print(z)  # This would cause an error - z is not defined in this scope

outer_function()
print(f"Global scope: x={x}")
# print(y)  # This would cause an error - y is not defined in this scope
```

Python follows the LEGB rule (Local, Enclosing, Global, Built-in) when looking up variables. It searches for a variable name first in the local scope, then in any enclosing scopes, then in the global scope, and finally in the built-in scope.

## 2. Nested Functions

Nested functions are functions defined inside other functions. They are useful for:
- Encapsulating helper functions that shouldn't be accessed from outside
- Creating closures
- Organizing complex code

```python
def outer(x):
    print(f"Outer function received: {x}")
    
    def inner(y):
        print(f"Inner function received: {y}")
        return x + y
    
    # We can either call inner directly
    result = inner(10)
    print(f"Result: {result}")
    
    # Or we can return the inner function itself
    return inner

# Using a nested function
func = outer(5)
print(f"Type of func: {type(func)}")

# Now we can call func as if it were inner
result = func(20)
print(f"Result of func(20): {result}")  # Will output 25 (5 + 20)
```

## 3. Closures Fundamentals

A closure is a function object that remembers values in the enclosing scope even if they are not present in memory. In other words, a closure "closes over" the free variables from its environment.

For a closure to exist, three conditions must be met:
1. There must be a nested function
2. The nested function must refer to a value defined in the enclosing function
3. The enclosing function must return the nested function

```python
def make_multiplier(x):
    def multiply(y):
        return x * y  # x is a free variable captured by the closure
    return multiply

# Create two different closures
times_3 = make_multiplier(3)
times_5 = make_multiplier(5)

# Use the closures
print(times_3(4))  # 12
print(times_5(4))  # 20

# We can inspect the closure
print(times_3.__closure__)
print(times_3.__closure__[0].cell_contents)  # Shows the value of x (3)
```

## 4. Creating and Using Closures

Let's explore more complex examples of closures:

```python
def counter_factory(start=0, step=1):
    count = start
    
    def counter():
        nonlocal count
        current = count
        count += step
        return current
    
    return counter

# Create counters with different configurations
counter_from_zero = counter_factory()
counter_from_ten = counter_factory(10)
counter_by_two = counter_factory(0, 2)

# Use the counters
print(counter_from_zero())  # 0
print(counter_from_zero())  # 1
print(counter_from_zero())  # 2

print(counter_from_ten())   # 10
print(counter_from_ten())   # 11

print(counter_by_two())     # 0
print(counter_by_two())     # 2
print(counter_by_two())     # 4
```

## 5. Nonlocal and Global Keywords

The `nonlocal` and `global` keywords allow us to modify variables in outer scopes:

```python
# Example using global
x = 10

def modify_global():
    global x
    x = 20
    print(f"Inside function: x = {x}")

print(f"Before function call: x = {x}")
modify_global()
print(f"After function call: x = {x}")

# Example using nonlocal
def outer_func():
    y = 10
    
    def inner_func():
        nonlocal y
        y = 20
        print(f"Inside inner function: y = {y}")
    
    print(f"Before inner function call: y = {y}")
    inner_func()
    print(f"After inner function call: y = {y}")

outer_func()
```

Without `nonlocal` or `global`, Python would create a new local variable instead of modifying the outer variable.

## 6. Common Use Cases for Closures

Closures are useful in several scenarios:

### Data Hiding / Encapsulation

```python
def create_account(initial_balance=0):
    balance = initial_balance
    
    def deposit(amount):
        nonlocal balance
        balance += amount
        return balance
    
    def withdraw(amount):
        nonlocal balance
        if amount <= balance:
            balance -= amount
            return balance
        return "Insufficient funds"
    
    def check_balance():
        return balance
    
    # Return a dictionary of operations
    return {
        "deposit": deposit,
        "withdraw": withdraw,
        "check_balance": check_balance
    }

# Create a bank account
account = create_account(1000)

# Use the account
print(account["check_balance"]())   # 1000
print(account["deposit"](500))      # 1500
print(account["withdraw"](200))     # 1300
print(account["withdraw"](2000))    # "Insufficient funds"
```

### Memoization (Caching)

```python
def memoize(func):
    cache = {}
    
    def wrapper(*args):
        if args in cache:
            print(f"Returning cached result for {args}")
            return cache[args]
        
        result = func(*args)
        cache[args] = result
        print(f"Calculated and cached result for {args}")
        return result
    
    return wrapper

@memoize
def fibonacci(n):
    if n <= 1:
        return n
    return fibonacci(n-1) + fibonacci(n-2)

# First call will calculate
print(fibonacci(10))  # Calculates recursively but with memoization

# Second call with the same argument will use cached results
print(fibonacci(10))  # Uses cached result
```

## 7. Function Factories

Function factories are functions that create and return other functions with specific behaviors:

```python
def power_function_factory(exponent):
    def power_function(base):
        return base ** exponent
    return power_function

# Create specialized power functions
square = power_function_factory(2)
cube = power_function_factory(3)
square_root = power_function_factory(0.5)

# Use the specialized functions
print(square(4))       # 16
print(cube(3))         # 27
print(square_root(16)) # 4.0

# More complex example: Creating customized formatters
def formatter_factory(template):
    def formatter(*args, **kwargs):
        return template.format(*args, **kwargs)
    return formatter

# Create specialized formatters
welcome_formatter = formatter_factory("Welcome, {0}! Your balance is ${1:.2f}")
error_formatter = formatter_factory("ERROR {code}: {message}")

# Use the formatters
print(welcome_formatter("Alice", 125.678))
print(error_formatter(code=404, message="Page not found"))
```

## 8. Closures vs. Classes

Both closures and classes can be used for similar purposes, but each has its strengths:

```python
# Implementing a counter with closure
def counter_closure(start=0):
    count = start
    
    def increment():
        nonlocal count
        count += 1
        return count
    
    return increment

# Implementing a counter with class
class CounterClass:
    def __init__(self, start=0):
        self.count = start
        
    def increment(self):
        self.count += 1
        return self.count

# Using the closure-based counter
counter1 = counter_closure(10)
print(counter1())  # 11
print(counter1())  # 12

# Using the class-based counter
counter2 = CounterClass(10)
print(counter2.increment())  # 11
print(counter2.increment())  # 12

# Comparison:
# Closure advantages:
# - Lighter weight (no need for self, __init__, etc.)
# - More concise for simple functionality
# - Useful for callbacks and decorators

# Class advantages:
# - More explicit and familiar to most programmers
# - Better for complex data with multiple methods
# - Can use inheritance and other OOP features
# - Better IDE support and introspection
```

## 9. Debugging Closures

Debugging closures can be challenging because of their nature. Here are some techniques:

```python
import inspect

def make_adder(x):
    def add(y):
        return x + y
    
    # Add some debug information
    add.__name__ = f"add_{x}"
    add.__qualname__ = f"make_adder.<locals>.add_{x}"
    
    return add

add_5 = make_adder(5)
add_10 = make_adder(10)

# Inspecting closures
print(f"Function name: {add_5.__name__}")
print(f"Closure cells: {add_5.__closure__}")
print(f"Closed value: {add_5.__closure__[0].cell_contents}")

# Get the source code
print(inspect.getsource(make_adder))

# Closure variables are also visible in debuggers
# Set a breakpoint on the next line and inspect add_5
result = add_5(3)

# Creating closures with built-in debugging
def debug_closure_factory(init_val):
    counter = init_val
    
    def increment(amount):
        nonlocal counter
        old_value = counter
        counter += amount
        print(f"DEBUG: counter changed from {old_value} to {counter}")
        return counter
    
    return increment

debug_counter = debug_closure_factory(5)
debug_counter(3)  # Outputs debug information
debug_counter(7)  # Outputs debug information
```

## 10. Best Practices

Here are some best practices when working with closures:

```python
# 1. Keep closures small and focused
def good_closure_factory(x):
    # Simple, focused closure with a clear purpose
    return lambda y: x + y

# 2. Use meaningful names
def temperature_converter(from_unit, to_unit):
    # Clear conversion factors
    conversion_factors = {
        ('C', 'F'): lambda c: c * 9/5 + 32,
        ('F', 'C'): lambda f: (f - 32) * 5/9,
        ('C', 'K'): lambda c: c + 273.15,
        ('K', 'C'): lambda k: k - 273.15,
        # Add more conversion factors as needed
    }
    
    # Get the appropriate conversion function
    key = (from_unit, to_unit)
    if key not in conversion_factors:
        raise ValueError(f"Conversion from {from_unit} to {to_unit} not supported")
    
    convert = conversion_factors[key]
    
    # Create a named closure with a clear interface
    def converter(value):
        """Convert a value from {from_unit} to {to_unit}"""
        return convert(value)
    
    return converter

# Create specialized converters
c_to_f = temperature_converter('C', 'F')
f_to_c = temperature_converter('F', 'C')

print(f"25°C = {c_to_f(25):.1f}°F")
print(f"98.6°F = {f_to_c(98.6):.1f}°C")

# 3. Document your closures
def documented_closure_factory(base_value):
    """
    Creates a function that adds a fixed base_value to its argument.
    
    Args:
        base_value: The fixed value to add to inputs
        
    Returns:
        A function that takes one argument and adds base_value to it
    """
    def add_base(x):
        """
        Add the base_value to the input value.
        
        Args:
            x: The value to add base_value to
            
        Returns:
            The sum of x and base_value
        """
        return base_value + x
    
    return add_base

# 4. Avoid modifying too many external variables
def bad_closure_example():
    a, b, c, d = 1, 2, 3, 4
    
    def modify_everything(x):
        nonlocal a, b, c, d
        a += x
        b += x
        c += x
        d += x
        return a + b + c + d
    
    return modify_everything

# Better to pass values explicitly or use a class instead
class BetterExample:
    def __init__(self, a, b, c, d):
        self.a = a
        self.b = b
        self.c = c
        self.d = d
    
    def modify_everything(self, x):
        self.a += x
        self.b += x
        self.c += x
        self.d += x
        return self.a + self.b + self.c + self.d

# 5. Be careful with loops and closures
def create_multipliers_wrong():
    multipliers = []
    for i in range(1, 6):
        # This doesn't work as expected because i is shared across all closures
        multipliers.append(lambda x: i * x)
    return multipliers

def create_multipliers_right():
    multipliers = []
    for i in range(1, 6):
        # This works because i is bound at function creation time
        multipliers.append(lambda x, i=i: i * x)
    return multipliers

wrong_multipliers = create_multipliers_wrong()
right_multipliers = create_multipliers_right()

print(wrong_multipliers[0](10))  # Expects 10, but gets 50 (5*10)
print(right_multipliers[0](10))  # Gets 10 as expected (1*10)
```

## Summary

- **Scopes** determine where variables can be accessed: local, enclosing, global, and built-in
- **Nested functions** are functions defined inside other functions
- **Closures** are functions that remember values from their enclosing scope
- **Nonlocal and global** keywords allow modifying variables in outer scopes
- **Function factories** create specialized functions for specific use cases
- Closures are useful for data hiding, callbacks, decorators, and maintaining state
- Closures and classes can solve similar problems but have different strengths
- When working with closures, keep them small, focused, well-named, and well-documented

Understanding closures deeply is important for Python programmers as they underpin many advanced features like decorators and context managers, and they provide elegant solutions for many programming challenges.
