## 1. Introduction to Object-Oriented Programming

Object-Oriented Programming (OOP) is a programming paradigm that uses "objects" – instances of classes – to structure code. Python is a multi-paradigm language that fully supports OOP. The fundamental concepts in OOP include:

- **Classes**: Blueprints for creating objects
- **Objects**: Instances of classes
- **Attributes**: Data stored in an object
- **Methods**: Functions that define what an object can do
- **Inheritance**: Creating new classes from existing ones
- **Polymorphism**: Different classes implementing the same interface

```python
# Basic class and object example
class Dog:
    # Class attribute
    species = "Canis familiaris"
    
    # Initializer / Constructor
    def __init__(self, name, age):
        # Instance attributes
        self.name = name
        self.age = age
    
    # Instance method
    def description(self):
        return f"{self.name} is {self.age} years old"
    
    # Another instance method
    def speak(self, sound):
        return f"{self.name} says {sound}"

# Creating instances of the Dog class
buddy = Dog("Buddy", 9)
miles = Dog("Miles", 4)

# Accessing attributes and methods
print(buddy.name)               # Output: Buddy
print(buddy.description())      # Output: Buddy is 9 years old
print(miles.speak("Woof Woof")) # Output: Miles says Woof Woof
```

## 2. Class Inheritance Basics

Inheritance allows us to define a class that inherits all the methods and properties from another class. The parent class is called the base class, and the child class is the derived class.

```python
# Base class
class Animal:
    def __init__(self, name, species):
        self.name = name
        self.species = species
        
    def make_sound(self):
        print("Some generic animal sound")
        
    def __str__(self):
        return f"{self.name} is a {self.species}"

# Derived class
class Dog(Animal):
    def __init__(self, name, breed):
        # Call the base class constructor
        super().__init__(name, "Dog")
        self.breed = breed
        
    def make_sound(self):
        print("Woof!")

# Another derived class
class Cat(Animal):
    def __init__(self, name, color):
        super().__init__(name, "Cat")
        self.color = color
        
    def make_sound(self):
        print("Meow!")

# Create objects of each class
generic_animal = Animal("Generic", "Animal")
dog = Dog("Buddy", "Golden Retriever")
cat = Cat("Whiskers", "Tabby")

# Accessing attributes and methods
print(generic_animal)  # Output: Generic is a Animal
generic_animal.make_sound()  # Output: Some generic animal sound

print(dog)  # Output: Buddy is a Dog
print(f"{dog.name} is a {dog.breed} {dog.species}")  # Output: Buddy is a Golden Retriever Dog
dog.make_sound()  # Output: Woof!

print(cat)  # Output: Whiskers is a Cat
cat.make_sound()  # Output: Meow!
```

## 3. Types of Inheritance

Python supports different types of inheritance:

1. **Single Inheritance**: A class inherits from a single parent class
2. **Multiple Inheritance**: A class inherits from multiple parent classes
3. **Multilevel Inheritance**: A class inherits from a child class
4. **Hierarchical Inheritance**: Multiple classes inherit from a single parent
5. **Hybrid Inheritance**: Combination of different inheritance types

```python
# Single Inheritance (already shown above with Dog and Animal)

# Multiple Inheritance
class Flyable:
    def fly(self):
        print("Flying high!")

class Swimmable:
    def swim(self):
        print("Swimming fast!")

class FlyingFish(Flyable, Swimmable):
    pass

# Multilevel Inheritance
class Vehicle:
    def __init__(self, name):
        self.name = name
    
    def get_name(self):
        return self.name

class Car(Vehicle):
    def __init__(self, name, model):
        super().__init__(name)
        self.model = model
    
    def get_details(self):
        return f"{self.get_name()} {self.model}"

class ElectricCar(Car):
    def __init__(self, name, model, battery_capacity):
        super().__init__(name, model)
        self.battery_capacity = battery_capacity
    
    def get_battery_info(self):
        return f"Battery capacity: {self.battery_capacity} kWh"

# Examples
flying_fish = FlyingFish()
flying_fish.fly()   # Output: Flying high!
flying_fish.swim()  # Output: Swimming fast!

tesla = ElectricCar("Tesla", "Model S", 100)
print(tesla.get_name())         # Output: Tesla
print(tesla.get_details())      # Output: Tesla Model S
print(tesla.get_battery_info()) # Output: Battery capacity: 100 kWh
```

## 4. Method Overriding and the super() Function

Method overriding occurs when a derived class provides a specific implementation for a method that is already defined in its base class. The `super()` function allows you to call methods from the parent class.

```python
class Shape:
    def __init__(self, color):
        self.color = color
        
    def area(self):
        # Base implementation
        return 0
    
    def describe(self):
        return f"A {self.color} shape with area: {self.area()}"

class Circle(Shape):
    def __init__(self, color, radius):
        super().__init__(color)
        self.radius = radius
        
    def area(self):
        # Override the area method
        return 3.14159 * (self.radius ** 2)

class Rectangle(Shape):
    def __init__(self, color, width, height):
        super().__init__(color)
        self.width = width
        self.height = height
        
    def area(self):
        # Override the area method
        return self.width * self.height
    
    def describe(self):
        # Override with additional information
        basic_description = super().describe()
        return f"{basic_description} (width: {self.width}, height: {self.height})"

# Create objects
circle = Circle("red", 5)
rectangle = Rectangle("blue", 4, 6)

# Call methods
print(circle.describe())    # Output: A red shape with area: 78.53975
print(rectangle.describe()) # Output: A blue shape with area: 24 (width: 4, height: 6)
```

## 5. Polymorphism in Python

Polymorphism allows different classes to have methods with the same name but different implementations. It promotes flexibility and reusability of code.

```python
# Polymorphism with a function
def describe_shape(shape):
    # This works for any object with a describe method
    return shape.describe()

# Polymorphism with iteration
shapes = [Circle("red", 5), Rectangle("blue", 4, 6), Circle("green", 8)]

# Call the same method on different objects
for shape in shapes:
    print(shape.describe())
    print(f"Area: {shape.area()}")
    print("---")

# Duck typing - a form of polymorphism
class Duck:
    def speak(self):
        return "Quack!"
    
    def walk(self):
        return "Walking like a duck."

class Person:
    def speak(self):
        return "Hello!"
    
    def walk(self):
        return "Walking like a person."

def make_it_talk_and_walk(entity):
    # No type checking - as long as the object has these methods, it works
    print(entity.speak())
    print(entity.walk())

make_it_talk_and_walk(Duck())
# Output:
# Quack!
# Walking like a duck.

make_it_talk_and_walk(Person())
# Output:
# Hello!
# Walking like a person.
```

## 6. Abstract Base Classes

Abstract Base Classes (ABCs) are classes that cannot be instantiated and require derived classes to implement specific methods. They act as a template for other classes.

```python
from abc import ABC, abstractmethod

class Animal(ABC):
    def __init__(self, name):
        self.name = name
    
    @abstractmethod
    def make_sound(self):
        """Each animal must implement this method"""
        pass
    
    def introduce(self):
        return f"I am {self.name}, and I sound like: {self.make_sound()}"

# This would raise an error if we tried to instantiate Animal directly:
# TypeError: Can't instantiate abstract class Animal with abstract method make_sound

class Dog(Animal):
    def make_sound(self):
        return "Woof!"

class Cat(Animal):
    def make_sound(self):
        return "Meow!"

# Create objects
dog = Dog("Buddy")
cat = Cat("Whiskers")

print(dog.introduce())  # Output: I am Buddy, and I sound like: Woof!
print(cat.introduce())  # Output: I am Whiskers, and I sound like: Meow!

# Using isinstance() with abstract base classes
print(isinstance(dog, Animal))  # Output: True
print(isinstance(cat, Animal))  # Output: True
```

## 7. Multiple Inheritance and Method Resolution Order

When a class inherits from multiple parent classes, Python uses the Method Resolution Order (MRO) to determine which method to call when there are methods with the same name in different parent classes.

```python
class A:
    def process(self):
        print("A's process")

class B:
    def process(self):
        print("B's process")

class C(A, B):
    pass

class D(B, A):
    pass

# Create objects
c = C()
d = D()

# Method resolution follows the order specified in inheritance
c.process()  # Output: A's process (A comes before B in C's inheritance)
d.process()  # Output: B's process (B comes before A in D's inheritance)

# Examine the MRO
print(C.__mro__)  
# Output: (<class '__main__.C'>, <class '__main__.A'>, <class '__main__.B'>, <class 'object'>)

print(D.__mro__)
# Output: (<class '__main__.D'>, <class '__main__.B'>, <class '__main__.A'>, <class 'object'>)

# Example with super() in multiple inheritance
class A:
    def process(self):
        print("A's process")
        return "A"

class B:
    def process(self):
        print("B's process")
        return "B"

class E(A, B):
    def process(self):
        result_a = super().process()  # Calls A's process based on MRO
        print(f"E's process, got {result_a} from parent")
        return "E"

e = E()
result = e.process()
# Output:
# A's process
# E's process, got A from parent
```

## 8. OOP Design Principles

When designing classes, it's important to follow certain principles:

1. **Encapsulation**: Bundle data and methods operating on that data within a class and restrict access to internal state
2. **Inheritance**: Model an "is-a" relationship between objects
3. **Polymorphism**: Provide a unified interface to objects of different types
4. **Abstraction**: Hide implementation details and show only functionality
5. **Composition**: Build complex objects from simpler objects (favor composition over inheritance)

```python
# Encapsulation example with private attributes
class BankAccount:
    def __init__(self, owner, initial_balance=0):
        self.owner = owner
        self._balance = initial_balance  # Protected attribute (convention)
        self.__transaction_log = []      # Private attribute (name mangling)
    
    def deposit(self, amount):
        if amount > 0:
            self._balance += amount
            self.__log_transaction("deposit", amount)
            return True
        return False
    
    def withdraw(self, amount):
        if 0 < amount <= self._balance:
            self._balance -= amount
            self.__log_transaction("withdraw", amount)
            return True
        return False
    
    def get_balance(self):
        return self._balance
    
    def __log_transaction(self, transaction_type, amount):
        # Private method
        import datetime
        self.__transaction_log.append({
            "type": transaction_type,
            "amount": amount,
            "timestamp": datetime.datetime.now()
        })

# Composition example
class Engine:
    def start(self):
        return "Engine started"
    
    def stop(self):
        return "Engine stopped"

class Car:
    def __init__(self, make, model):
        self.make = make
        self.model = model
        # Composition: Car has-an Engine
        self.engine = Engine()
    
    def start(self):
        return f"{self.make} {self.model}: {self.engine.start()}"
    
    def stop(self):
        return f"{self.make} {self.model}: {self.engine.stop()}"

# Examples
account = BankAccount("John Doe", 1000)
print(account.get_balance())  # Output: 1000
account.deposit(500)
print(account.get_balance())  # Output: 1500
account.withdraw(200)
print(account.get_balance())  # Output: 1300

# Access protection
print(account._balance)      # Accessible but not recommended
# print(account.__transaction_log)  # This would raise an AttributeError

my_car = Car("Toyota", "Corolla")
print(my_car.start())  # Output: Toyota Corolla: Engine started
print(my_car.stop())   # Output: Toyota Corolla: Engine stopped
```

## 9. Practical Applications

Let's see how inheritance and polymorphism can be applied in real-world scenarios:

```python
# Example: Employee Management System
class Employee:
    def __init__(self, name, id_number):
        self.name = name
        self.id_number = id_number
        
    def get_salary(self):
        # Abstract method to be implemented by subclasses
        raise NotImplementedError("Subclasses must implement get_salary()")
    
    def display_info(self):
        return f"Employee {self.name} (ID: {self.id_number})"

class HourlyEmployee(Employee):
    def __init__(self, name, id_number, hourly_rate, hours_worked):
        super().__init__(name, id_number)
        self.hourly_rate = hourly_rate
        self.hours_worked = hours_worked
        
    def get_salary(self):
        return self.hourly_rate * self.hours_worked
    
    def display_info(self):
        base_info = super().display_info()
        return f"{base_info}, Hourly rate: ${self.hourly_rate:.2f}/hour"

class SalariedEmployee(Employee):
    def __init__(self, name, id_number, annual_salary):
        super().__init__(name, id_number)
        self.annual_salary = annual_salary
        
    def get_salary(self):
        return self.annual_salary / 12  # Monthly salary
    
    def display_info(self):
        base_info = super().display_info()
        return f"{base_info}, Annual salary: ${self.annual_salary:.2f}"

class CommissionedEmployee(SalariedEmployee):
    def __init__(self, name, id_number, annual_salary, commission_rate, sales):
        super().__init__(name, id_number, annual_salary)
        self.commission_rate = commission_rate
        self.sales = sales
        
    def get_salary(self):
        base_salary = super().get_salary()
        commission = self.commission_rate * self.sales
        return base_salary + commission
    
    def display_info(self):
        base_info = super().display_info()
        return f"{base_info}, Commission rate: {self.commission_rate:.1%}"

# Payroll system that works with any type of Employee
def process_payroll(employees):
    print("Processing payroll...")
    for emp in employees:
        print(f"{emp.display_info()}")
        print(f"Monthly salary: ${emp.get_salary():.2f}")
        print("---")

# Create employees
employees = [
    HourlyEmployee("John Smith", "H001", 20.0, 160),
    SalariedEmployee("Jane Doe", "S001", 60000.0),
    CommissionedEmployee("Alice Johnson", "C001", 50000.0, 0.05, 30000.0)
]

# Process payroll for all employees
process_payroll(employees)
```

## 10. Summary

Object-Oriented Programming in Python provides powerful tools for structuring and designing code:

1. **Classes and Objects** form the foundation of OOP, allowing you to model real-world entities as software objects with attributes and behaviors.

2. **Inheritance** enables code reuse by creating new classes that inherit attributes and methods from existing ones. Python supports single, multiple, and multilevel inheritance.

3. **Method Overriding** lets you redefine methods in derived classes to provide specific implementations while maintaining the same interface.

4. **Polymorphism** allows you to treat objects of different classes that implement the same interface in a similar way, promoting flexibility and extensibility.

5. **Abstract Base Classes** help define interfaces that derived classes must implement, ensuring consistency across class hierarchies.

6. **Multiple Inheritance** and the Method Resolution Order (MRO) provide flexibility but require careful design to avoid complexity.

7. **OOP Design Principles** such as encapsulation, inheritance, polymorphism, abstraction, and composition guide you in creating maintainable and extensible code.

By mastering these concepts, you can create well-structured, maintainable, and extensible Python applications. OOP helps manage complexity in large systems by organizing code around objects that model real-world concepts, making your code more intuitive and easier to understand.
