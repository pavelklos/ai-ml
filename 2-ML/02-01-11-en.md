## 1. Introduction to Overfitting and Underfitting

Overfitting and underfitting are fundamental concepts in machine learning that describe how well a model generalizes to new, unseen data after training.

- **Overfitting** occurs when a model learns the training data too well, capturing noise and random fluctuations rather than the underlying pattern. These models perform excellently on training data but poorly on new data.

- **Underfitting** happens when a model is too simple to capture the underlying structure of the data. These models perform poorly on both training and test data.

```python
# Import essential libraries
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.model_selection import train_test_split, learning_curve
from sklearn.linear_model import LinearRegression, Lasso, Ridge
from sklearn.preprocessing import PolynomialFeatures

from sklearn.tree import DecisionTreeRegressor

# Set random seed for reproducibility
np.random.seed(42)
```

## 2. Understanding the Bias-Variance Tradeoff

The bias-variance tradeoff is a central concept related to overfitting and underfitting:

- **High Bias (Underfitting)**: Model makes strong assumptions about the data, resulting in a simple model that misses important patterns
- **High Variance (Overfitting)**: Model is highly sensitive to small fluctuations in the training data

```python
# Generate synthetic data to demonstrate bias-variance tradeoff
def generate_nonlinear_data(n_samples=100, noise=0.5):
    """Generate nonlinear data with some noise"""
    X = np.random.uniform(0, 10, size=n_samples).reshape(-1, 1)
    y = np.sin(X).ravel() + noise * np.random.randn(n_samples)
    return X, y

# Create dataset
X, y = generate_nonlinear_data(200)

# Split data into training and testing sets
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=42)

# Plot the data
plt.figure(figsize=(10, 6))
plt.scatter(X_train, y_train, alpha=0.7, label='Training data')
plt.scatter(X_test, y_test, alpha=0.7, label='Test data')
plt.title('Nonlinear Data')
plt.xlabel('X')
plt.ylabel('y')
plt.legend()
plt.show()
```

## 3. Identifying Overfitting and Underfitting

You can identify overfitting and underfitting by comparing performance metrics on training and test datasets:

- **Underfitting**: High training error, high test error
- **Good fit**: Low training error, low test error
- **Overfitting**: Low training error, high test error

```python
def evaluate_model(model, X_train, y_train, X_test, y_test):
    """Train model and evaluate on train and test data"""
    model.fit(X_train, y_train)
    
    # Make predictions
    train_preds = model.predict(X_train)
    test_preds = model.predict(X_test)
    
    # Calculate MSE
    train_mse = mean_squared_error(y_train, train_preds)
    test_mse = mean_squared_error(y_test, test_preds)
    
    print(f"Training MSE: {train_mse:.4f}")
    print(f"Test MSE: {test_mse:.4f}")
    
    return train_mse, test_mse, model

# Create models with different complexities
models = {
    "Underfitting (Linear)": LinearRegression(),
    "Good Fit (Polynomial - degree 3)": make_pipeline(PolynomialFeatures(3), LinearRegression()),
    "Overfitting (Polynomial - degree 15)": make_pipeline(PolynomialFeatures(15), LinearRegression()),
}

# Evaluate each model
results = {}
for name, model in models.items():
    print(f"\nEvaluating: {name}")
    train_mse, test_mse, fitted_model = evaluate_model(model, X_train, y_train, X_test, y_test)
    results[name] = {
        'model': fitted_model,
        'train_mse': train_mse,
        'test_mse': test_mse
    }
```

## 4. Visualizing Model Complexity

## 5. Techniques to Prevent Overfitting

Several techniques can help prevent overfitting:

### Regularization

```python
# Demonstrate regularization with Ridge and Lasso regression
degree = 10  # High polynomial degree (prone to overfitting)

# Create models with different regularization strengths
models = {
    "No Regularization": make_pipeline(PolynomialFeatures(degree), LinearRegression()),
    "Ridge (L2)": make_pipeline(PolynomialFeatures(degree), Ridge(alpha=1.0)),
    "Lasso (L1)": make_pipeline(PolynomialFeatures(degree), Lasso(alpha=0.01))
}

# Evaluate regularized models
reg_results = {}
for name, model in models.items():
    print(f"\nEvaluating: {name}")
    train_mse, test_mse, fitted_model = evaluate_model(model, X_train, y_train, X_test, y_test)
    reg_results[name] = {
        'model': fitted_model,
        'train_mse': train_mse,
        'test_mse': test_mse
    }
```

### Early Stopping and Pruning

```python
# Demonstrate early stopping with decision trees
# Create and evaluate unpruned tree
deep_tree = DecisionTreeRegressor(max_depth=None)
deep_train_mse, deep_test_mse, _ = evaluate_model(deep_tree, X_train, y_train, X_test, y_test)

# Create and evaluate pruned tree
pruned_tree = DecisionTreeRegressor(max_depth=3)  # Limit depth
pruned_train_mse, pruned_test_mse, _ = evaluate_model(pruned_tree, X_train, y_train, X_test, y_test)

print("\nUnpruned vs Pruned Decision Tree:")
print(f"Unpruned - Train MSE: {deep_train_mse:.4f}, Test MSE: {deep_test_mse:.4f}")
print(f"Pruned  - Train MSE: {pruned_train_mse:.4f}, Test MSE: {pruned_test_mse:.4f}")
```

### Dropout and Ensemble Methods

```python
from sklearn.ensemble import RandomForestRegressor

# Demonstrate ensemble methods to prevent overfitting
forest = RandomForestRegressor(n_estimators=100, random_state=42)
forest_train_mse, forest_test_mse, _ = evaluate_model(forest, X_train, y_train, X_test, y_test)

print("\nDecision Tree vs Random Forest:")
print(f"Decision Tree - Train MSE: {deep_train_mse:.4f}, Test MSE: {deep_test_mse:.4f}")
print(f"Random Forest - Train MSE: {forest_train_mse:.4f}, Test MSE: {forest_test_mse:.4f}")
```

## 6. Techniques to Address Underfitting

To address underfitting, you generally need to increase model complexity:

```python
# Demonstrate addressing underfitting
models = {
    "Linear (Underfitting)": LinearRegression(),
    "Polynomial degree 2": make_pipeline(PolynomialFeatures(2), LinearRegression()),
    "Polynomial degree 3": make_pipeline(PolynomialFeatures(3), LinearRegression()),
    "Complex Model (Decision Tree)": DecisionTreeRegressor(max_depth=5)
}

# Evaluate models with increasing complexity
for name, model in models.items():
    print(f"\nEvaluating: {name}")
    train_mse, test_mse, _ = evaluate_model(model, X_train, y_train, X_test, y_test)
```

Strategies to address underfitting include:
- Adding more relevant features
- Increasing model complexity (e.g., higher degree polynomials)
- Reducing regularization strength
- Using more powerful model architectures
- Feature engineering to better capture patterns

## 7. Cross-validation for Model Selection

Cross-validation helps identify the optimal level of model complexity, balancing the trade-off between overfitting and underfitting.

```python
from sklearn.model_selection import cross_val_score

# Use cross-validation to select optimal polynomial degree
degrees = range(1, 15)
cv_scores = []

for degree in degrees:
    model = make_pipeline(PolynomialFeatures(degree), LinearRegression())
    scores = cross_val_score(model, X, y, cv=5, scoring='neg_mean_squared_error')
    cv_scores.append(-scores.mean())  # Convert to positive MSE

# Find optimal degree
optimal_degree = degrees[np.argmin(cv_scores)]
print(f"Optimal polynomial degree: {optimal_degree}")

# Plot cross-validation results
plt.figure(figsize=(10, 6))
plt.plot(degrees, cv_scores, marker='o')
plt.axvline(x=optimal_degree, color='r', linestyle='--', label=f'Optimal degree: {optimal_degree}')
plt.xlabel('Polynomial Degree')
plt.ylabel('Cross-Validation MSE')
plt.title('Cross-Validation for Model Selection')
plt.grid(True, alpha=0.3)
plt.legend()
plt.show()
```

## 8. Practical Examples with Different Models

Let's see how overfitting and underfitting manifest in different machine learning models:

```python
from sklearn.datasets import load_boston
from sklearn.model_selection import learning_curve
from sklearn.svm import SVR

# Load a real-world dataset
boston = load_boston()
X_boston, y_boston = boston.data, boston.target

# Split the data
X_train, X_test, y_train, y_test = train_test_split(
    X_boston, y_boston, test_size=0.2, random_state=42)

# Function to plot learning curves
def plot_learning_curve(estimator, title, X, y, ylim=None, cv=5,
                        n_jobs=None, train_sizes=np.linspace(.1, 1.0, 5)):
    plt.figure(figsize=(10, 6))
    plt.title(title)
    if ylim is not None:
        plt.ylim(*ylim)
    plt.xlabel("Training examples")
    plt.ylabel("Score")
    
    train_sizes, train_scores, test_scores = learning_curve(
        estimator, X, y, cv=cv, n_jobs=n_jobs, train_sizes=train_sizes, scoring='neg_mean_squared_error')
    
    train_scores_mean = -np.mean(train_scores, axis=1)
    test_scores_mean = -np.mean(test_scores, axis=1)
    
    plt.grid()
    plt.plot(train_sizes, train_scores_mean, 'o-', color="r", label="Training score")
    plt.plot(train_sizes, test_scores_mean, 'o-', color="g", label="Cross-validation score")
    plt.legend(loc="best")
    
    return plt

# Models to demonstrate overfitting and underfitting
models = {
    "Linear Regression (Underfitting)": LinearRegression(),
    "Decision Tree (Overfitting)": DecisionTreeRegressor(),
    "SVR with RBF Kernel (Good Fit)": SVR(kernel='rbf', C=1.0, gamma='scale')
}

for name, model in models.items():
    plot_learning_curve(model, f"Learning Curve - {name}", X_boston, y_boston)
    plt.show()
```

## 9. Summary

Understanding overfitting and underfitting is essential for building effective machine learning models:

- **Overfitting** occurs when models are too complex for the data, capturing noise rather than real patterns
- **Underfitting** happens when models are too simple to capture the underlying patterns in the data
- The **bias-variance tradeoff** is central to managing these issues:
  - High bias leads to underfitting
  - High variance leads to overfitting

Key strategies for addressing these issues:

- **For overfitting**: 
  - Regularization (L1, L2)
  - More training data
  - Feature reduction
  - Early stopping
  - Ensemble methods
  - Dropout (for neural networks)

- **For underfitting**:
  - Increase model complexity
  - Feature engineering
  - Reduce regularization
  - Use more powerful models

- **For finding the right balance**:
  - Cross-validation
  - Learning curves
  - Monitoring training and validation metrics

Remember that the goal is not to perfectly fit the training data, but to build a model that generalizes well to new, unseen data.
